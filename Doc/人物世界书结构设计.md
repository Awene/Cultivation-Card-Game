# 人物世界书结构设计

> 与 [角色蓝图.csv](角色蓝图.csv) 配套的文件分组与路由设计。下方保留凡界既有分组；灵界新增分组、人数与路径见 [灵界人物落地清单.md](灵界人物落地清单.md)。
> 文件命名 / 路径约定：`世界书/<世界>/<地域>/人物/[mvu_plot]人物-<地域>-<分组名>.txt`。同宗男女共用文件；凡国、城市民间人物和独立组织分别分组。

---

## 一、设计原则

1. **同宗→同文件**：宗门/组织内所有成员合在一个文件，文件内部用 EJS 按角色名/道号路由输出。
2. **王朝公主细分**：不同凡国（甚至不同城市）拆成独立文件，留扩充空间。
3. **散修异士细分**：每个城市/邪派/族裔单独成文，哪怕暂时只 1 人；将来加新 NPC 直接进同文件。
4. **绿灯触发原则**：文件 yaml 关键字 = **内部所有角色名 + 道号 + 宗门/族/城/标志地标**。任一命中即激活全文件，EJS 内部决定输出哪位角色的 detail。
5. **顺序约定**：当前人物绿灯条目使用 `顺序: 200`，位于人物包装条目的 151 与 250 之间；旧版 56 不再适用，须与现有 YAML 的包装区间一致。

## 三、EJS 内部路由模板

每个文件统一遵循的输出逻辑：

```ejs
<%_ { _%>
<%_
// 1) 读 chat 与 stat_data，拼成扫描文本
const 具体地点 = getMessageVar('stat_data.地点.具体地点') || '';
let scanText = 具体地点;
try {
  const array = x => Array.isArray(x) ? x : x ? [x] : [];
  // ST-Prompt-Template：负数从尾部取；正数是头部条数，不是最近条数。
  const recent = array(getChatMessages(-10));
  scanText += '\n' + recent.map(m => typeof m === 'string' ? m : String(m?.message ?? m?.content ?? '')).join('\n');
} catch(e) {}
const mentioned = (kws) => kws.some(kw => kw && scanText.includes(kw));

// 2) 角色字典：每位一份 brief（一句话名片）与 detail（完整人设）
const C = {
  '白羽弦': {
    kws: ['白羽弦'],              // 个人触发关键字（多含本名+道号）
    brief: `- 白羽弦(女·化神中期·聆风斋斋主)：清音律承嗣、慈悲护道`,
    detail: `### 白羽弦
- 道号/职位：聆风斋斋主、清音律承嗣
- 境界：化神中期
- 外观：御姐 / 墨发盘髻素玉簪、淡紫眸、肤白胜玉
- 性格：心怀慈悲、把抚琴当治病救人...
- 着装：月白广袖琴袍、白绫齐胸...
- 关系网：...`
  },
  '林幽笛': { kws: ['林幽笛'], brief: `...`, detail: `...` },
  '顾流商': { kws: ['顾流商'], brief: `...`, detail: `...` },
};

// 3) 路由策略
const hitChars = Object.entries(C).filter(([n, c]) => mentioned(c.kws));
const sectKws = ['聆风斋', '清音律', '回音谷'];  // 文件级（宗门）关键字
const sectHit = mentioned(sectKws);

let outputText = '';
if (hitChars.length > 0) {
  // 命中具体角色 → 输出 detail
  outputText = hitChars.map(([n, c]) => c.detail).join('\n\n');
  // 若同时命中宗门 → 附其他成员 brief 作环境
  if (sectHit) {
    const others = Object.entries(C).filter(([n]) => !hitChars.find(([h]) => h === n));
    if (others.length) {
      outputText += '\n\n[同宗其他人物]\n' + others.map(([n, c]) => c.brief).join('\n');
    }
  }
} else if (sectHit) {
  // 仅命中宗门 → 输出全部 brief（人物名册）
  outputText = '[聆风斋人物名册]\n' + Object.values(C).map(c => c.brief).join('\n');
}
_%>
<%- outputText %>
<%_ } _%>
```

**输出三档**：
- **角色命中**（chat 提到本名/道号）→ 该角色 detail
- **宗门命中**（chat 只提宗门/地标）→ 全部成员 brief
- **角色+宗门同时命中** → 角色 detail + 其他成员 brief

## 五、命名 / 路径规范

| 项        | 规则                                                               |
| --------- | ------------------------------------------------------------------ |
| 文件名    | `[mvu_plot]人物-<region>-<分组名>.txt`                             |
| 物理路径  | `世界书/<世界>/<region>/人物/[mvu_plot]人物-<region>-<分组名>.txt` |
| yaml 名称 | 与文件名同名（去 `.txt`）                                          |
| 触发顺序  | `200`（当前人物包装开始 151、结束 250）                            |

**`<分组名>`** 优先级：
- 大宗门名 → `聆风斋` / `玉女宗` / `万妖盟-潜龙族`
- 凡国/王朝名 → `沧澜王朝` / `楚天王朝` / `乾元皇室`
- 官署名 → `北辰学宫` / `镇魔司`
- 单一城市/势力 → `烬阳城` / `临渊城` / `净世军`
- 异族/特殊 → `碧落海族` / `雾林木灵`

## 六、扩充指南（将来加新人）

1. **新角色属于已有分组** → 直接打开对应文件，往 `C` 字典里加一条 `{kws, brief, detail}`；同时在 yaml `关键字` 里加该角色本名/道号。
2. **新角色属于已有大区但无对应分组**（如新城市 NPC）→ 新建 `[mvu_plot]人物-<region>-<新分组>.txt`，仿模板写一份。
3. **跨region 角色**（如某人物在两个 region 都活跃）→ 放在主要驻地的文件里，次驻 region 的 yaml 关键字也可挂上她的本名。
4. **男性人物**：未来若要补男角色，同样按"宗门→分组→文件"逻辑，命名为 `[mvu_plot]人物-<region>-<分组>.txt`（不区分性别，同一宗门男女在同一文件里更方便路由）。

## 七、与 [角色蓝图.csv](角色蓝图.csv) 的映射

蓝图 csv 是**人设池**，本结构是**世界书载体**。映射关系：
- csv 一行 = 一位角色。原有 11 列保持名称与顺序：人物名称、性别、关键字、初遇地点、外观、女性魅力、外观特征、穿衣习惯(外)、穿衣习惯(内)、性格特征、常用法宝类型。
- 灵界追加列：世界、大陆、种族、初始境界、实际年龄、所属分组、身份职责、人物世界书文件、说话方式、生活习惯、初遇情境、关系与交往、可选故事。既有凡界行追加列留空，不反向猜测历史资料。
- 世界书文件 `C[名字].detail` = 把那一行展开成完整人设段落
- 世界书文件 `C[名字].brief` = 那一行的浓缩名片
- 世界书 yaml `关键字` = csv 「关键字」列直接复用 + 该文件统一附加的宗门/地标 kws

填充时对照完整 CSV 行及大陆蓝图。男性的「女性魅力」可填不适用。衣饰须符合物种及化形状态，不给水生原身强加人类衣裤。具体岁数照录，未定者明确标记，不由境界反推年龄。

### 灵界落地补充

- 女性外观统一为「御姐／少女／萝莉」，均为成年人；外观不替代实际年龄。
- `C` 保留 `kws / brief / detail`，另拆分 `initial / sourceProfile / knownBrief`。未出场才输出完整初始身份、境界、形貌及已定档案；关系列表已有者使用既有人物提示，不回写或重置 MVU。
- `detail` 的说话、生活、初遇、关系与故事均为创作参考。已出场以实际剧情为准，不重演初遇，不自动告白、赠宝或绑定关系。可选故事不能当作已发生事件。
- 仅命中个人展开该人详情；只命中组织显示全组名册；同时命中附其余成员名册。个人与组关键词分离。
- 灵界条目只在灵界输出，可通过姓名跨大陆触发，支持旅行和通信。聊天接口缺失仍可按地点显示名册；递归不可激活其他条目。
- 每份 EJS 使用独立块作用域。当前 EJS 由 ST-Prompt-Template 提供：本机实现 `getChatMessages(10)` 取开头十条，`getChatMessages(-10)` 取最近十条，返回 `string[]`。不能套用酒馆助手的字符串范围、`message_id` 或 `hide_state` 参数。本插件不以该参数过滤隐藏楼层，勿宣称已自动过滤。此前将正数解释为第 10 条的说明已纠正。
- 总览保留地理、组织及基础名册，人物文件承担扩写人设与生活细节。新增故事不倒填成世界历史；本轮不改原有凡界人物的关系阶段机制。
- 维护与核验入口见 [灵界人物落地清单.md](灵界人物落地清单.md)。

### 第二版人物深写要求

第一版五项短提示不足以承担完整人设。第二版以 [人物提示词示例.txt](人物提示词示例.txt) 为内容标准、凡界人物成品为表现参考：每人角色魅力、内外衣饰、法宝类型、完整底色；两项性格各三个生活场景；主动表白一段；道侣相处四段。场景必须体现动作、对白、欲望、反差或缺点，不以增加标签或重复规则句凑篇幅。

审稿时尤其注意：

- 职责不能占满人格。性格情境中应有纯粹的趣事、偏好、才华和没有立刻改掉的小毛病，不把每段都写成「问题—提醒—认错—道理」。
- 道侣日常要有自然的亲近、玩笑、想念和共同趣味，不能四段全是公务争论或关系协商；不同人物应有不同的声音和相处节奏。
- 表白重点是此人怎样准备、怎样开口、怎样掩饰紧张及其专属台词。成年、关系前提和尊重拒绝由统一模板说明，不逐段重复，以免挤占人物正文。
- 场景遵循身体与环境：水下饮用采用封口容器或已有明确干室，不默认敞口倒水；鱼尾、翼根、腕足、植灵与原身的动作、衣饰、作息分别推敲，不只给人类生活换物种名。
- 数量、篇幅、字段和重复检查是底线，不是文学质量结论。按小批次抽查并回修后继续，不靠机械复用情境补齐人数。

人物详情采用可读的多行文本。`表白` 与 `道侣` 单独存储：已出场、非道侣且好感度大于 80 时才提供表白演绎参考；已有道侣关系时才提供四段相处参考。阈值不自动执行表白或更改关系，既有剧情始终优先。身体与情感均遵循已确认的成年设定；非人形不强行套用人类衣饰与亲密动作。

CSV 在原 24 列后追加「性格底色、性格特征A、性格A场景、性格特征B、性格B场景、主动表白、道侣相处」，保留旧字段与凡界记录。具体接口更正及全库审计见 [世界书接口与顺序审计.md](世界书接口与顺序审计.md)。
