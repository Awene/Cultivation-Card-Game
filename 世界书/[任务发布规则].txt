<rule name="任务发布规则">
# 触发与定位
  - 本面板为<user>当前追踪的“进行中事项”，涵盖【委托任务】与【奇遇/事件】两大类。
  - 仅在委托明确成立、事件进入跨回合决策状态机，或既有事项状态发生实质阶段推进时输出面板，并同步写入 stat_data.任务。
  - 闲谈传闻、线索提及、未经确认的口头请求，以及一轮即结的日常小事件严禁建卡。

# 命名与路径铁律
  - 事项名称必须为纯中文短语（4~8字，如“残简之秘”、“水乡避雨”），严禁包含间隔号(·)、斜杠(/)、波浪号(~)及任何标点符号。
  - JSON Patch 路径中严禁对名称使用 ~1 转义，直接使用原名称（例如 /任务/残简之秘/状态，严禁写成 /任务/残简之秘~1...）。

# 输出格式
  输出前以 <!-- ... --> 核对触发条件、分类模式及面板与变量的一致性。

  [模式一：委托任务]（有人托付、有明确交付与酬劳）
  <task_info>
    {任务名称}
    | 状态: [进行中|待结算] | 难度: [境界] |
    | 委托方: [人物或组织] | 截止时间: [YYYY年M月D日时辰|无] |
    | 目标: [一句话达成条件] |
    | 进展: [当前最新进展] |
    | 奖励: [具体奖励] |
    | 交付: [对象、地点与交付条件] |
  </task_info>

  [模式二：奇遇/事件/危机]（自发遭遇、机缘现世、险境对峙；无固定委托人）
  <task_info>
    {事件名称}
    | 状态: [进行中|待结算] | 难度: [境界] |
    | 委托方: 机缘 | 截止时间: [紧迫时间|无] |
    | 目标: [核心诉求或破局条件] |
    | 进展: [当前局势或状态机阶段] |
  </task_info>
  <!-- 注：事件模式下无需生搬硬套“奖励”与“交付”，前端会自动隐藏未填项保持卡片紧凑 -->

# 状态机协同规范
  - 事项开启/推进：写入 stat_data.任务，状态为 [进行中]
  - 目标达成/待领奖/待终局：状态变更为 [待结算]
  - 交付领奖/事件完结/失败放弃：自 stat_data.任务 中彻底移除此条目（{ "op": "remove", "path": "/任务/{名称}" }），保持状态栏清爽。
</rule>
