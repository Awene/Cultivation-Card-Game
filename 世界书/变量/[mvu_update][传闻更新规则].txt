本规则供变量更新AI执行。正文提到传闻不等于变量已经更新，必须将实际操作并入本轮既有<UpdateVariable>的同一个<JSONPatch>数组。

# 一、确认结算区间
- 起点S为推演前的传闻.上次世界推进时间点，终点T为本轮世界推进请求记录的玩家当前时间（年、月、日、时辰）。不得从NPC中途镜头重新推算终点。
- 仅在T>S且本轮推演完成、镜头已回到玩家当前时间时结算。失败、未完成、日期无效或终点不明时不标记完成，不猜测或重置起点。
- 当前变量是已结算事实。只补记尚未结算的NPC和世界变化，不重复给主角发放已结算的闭关修为、年龄、灵石或物品。例如上一轮已结算30日修炼，本轮回顾这30日不能再加一次修为；听到悬赏不等于完成任务或得到奖励。

# 二、固定分类与维护数量
传闻.条目仍是原格式数组，不改成按类别索引的对象。使用下列10个固定类别，每次成功完成世界推进后，整个数组中每类恰好一条，共10条；不是每个地域各10条，也不是每轮再追加10条。类别名称必须与表中一致，不增设“其他”或自行拆分子类。

| 类别 | 消息内容与边界 |
| --- | --- |
| 秘境传闻 | 未知古洞、小型秘境入口或探索线索；官方秘境遵循既定开放周期 |
| 高额悬赏 | 公开的护送、搜寻、采集或讨伐委托，说明目标、发布渠道与线索 |
| 妖兽异动 | 兽群迁徙、巢穴扩张、商路受袭等，符合当地生态 |
| 通缉魔修 | 公开的罪行、特征与追捕线索，不因修炼流派就认定有罪 |
| 宝物现世 | 遗物、奇物、矿脉或失落宝藏的踪迹，不等于玩家已获得宝物 |
| 灵植奇遇 | 灵植成熟、药园遗迹、资源群落及守护情况 |
| 坊市集会 | 交易集会、拍卖、物资交流的时间、地点和可参与内容 |
| 灵气潮汐 | 局部灵气、五行或天象的变化及观察线索，不擅自改全局数值规则 |
| 古迹奇谭 | 古迹传说、碑文、遗址异象与可调查的谜团，区别于已确认的秘境入口 |
| 时空裂缝 | 空间异常、短暂裂隙或疑似异界通道；低境界也可听闻，不代表能进入或跨界 |

维护步骤:
1. 读取完整旧数组，先按类别归组。同一类别若有多条，优先保留玩家正在调查的事件，其次保留本轮明确推进的事件，再选仍有效、与当前区域最相关的一条；仍相同时优先消息日期较新者。不要把多个独立事件拼成一条来绕过数量限制。
2. 结束日期早于T的年月日才算过期，结束当天仍有效；正文明确证伪、取消或已消失的机会也应清理。尚未开始但已公开预告的活动可保留。
3. 同一对象、地点、因果链的后续消息沿用旧id，更新内容、有效期等，不重复新增；没有进展的消息不刷新id或无理由延长有效期。
4. 有效旧消息优先沿用，不必每轮全部换新。新消息与旧消息同类时，在原类别槽位中择一或更新；旧消息被替代不等于事件未发生，也不删除已接取的任务。其他地域的有效旧消息同样可占据该类槽位，但全局仍只能一条。
5. 缺失、空内容、过期或证伪而空出的类别必须补齐；旧数组为空时一次初始化全部10类。补齐后按上表顺序排列，核验类别不重不漏。完成状态不能以空数组、空字符串或“暂无消息”占位。
6. 旧存档类别映射：怪物异动→妖兽异动、通缉要犯→通缉魔修、宝物传闻→宝物现世、冒险发现→秘境传闻。其他旧类别按实际内容归入最贴切的一类，再执行去重；只改类别而事件本身没变时保留id。

# 三、提取公开新消息
- 优先使用本轮正文和旧传闻，提取坊市告示、商旅报告、宗门公开调度、兽群活动等可传播事件，归入对应类别更新。不能只在Analysis中写“传闻已更新”。同类有多个新线索时按第二节择一，不突破每类一条。
- 每条用1至3句交代来源、发生地、消息内容及可调查/参与的线索。不确定内容用“据说”“传闻”；私密修炼、密谈等NPC镜头不能直接变成公开情报，除非有明确传播渠道。
- 对正文没有涉及、旧消息又无法沿用的空缺类别，变量更新AI获准依据世界设定、当前年月、玩家所在世界与地域补充一条背景传闻。它可以是已存在一段时间、现在经商旅/告示传来的线索，不必声称在本轮短区间内突然发生。此权限仅用于补齐公开背景消息，不扩展为任意改写人物或世界重大事实。
- 背景消息不必围绕玩家经历展开。优先使用当地自然地标、无名委托或未具名修士，不虚构已有NPC的死亡、突破、罪行、私生活，不虚构宗门覆灭或官方秘境提前开放。同一事件只归入一个主要类别，不将同一洞府发现换十种说法填满各类。
- 已公开的具体宗门/人物可以指名；没有依据时不杜撰已有NPC的突破、死亡、私事或物品转移。地点、兽群、灵植须符合当地生态，官方秘境遵守既有开放规则。奖金额度、物品品质和境界遵循世界书及正文，不照抄旧脚本的随机公式。
- 不按概率抽取类别，每类一条是完成结算的数量约束。时间跨度短时尽量保留有效旧消息，只补缺项；不为刷新10类而强行制造10起新事故。无变化时保留完整10条，仅更新完成时间点。

# 四、字段要求
传闻是对象，包含上次世界推进时间点和条目数组；不得将它改回数组。每个条目包含：
- id: 唯一且稳定的非空字符串。新id可用“世界-地域-年月日-事件短名-序号”，先检查不与旧id重复。
- 时间区间: {起:{年:number,月:number,日:number},止:{年:number,月:number,日:number}}。这是消息有效期，不是推演区间；使用每月30日、每年12月的日历，起不得晚于止。优先依据明确的公告和截止日期；未明确期限的一般线索按事件性质给出合理保鲜期，不统一套用多年时长。预告不等于事件已发生。
- 世界、地域、地点: 字符串，记录事件发生地，地点尽量包含可查找的地域/地标，不强制等于玩家当前位置。
- 类别: 第二节固定10类之一。内容: 非空字符串，不能残留模板占位符或用“无事发生”代替具体线索。
- 难度: 参与/调查的建议境界，如“炼气初期-筑基初期”，按实际风险填写，不因玩家弱而降低风险。依据不足写“待查”，不凭空设定敌人实力。

# 五、JSONPatch操作
1. 先计算完整结果数组：分类归一→清理过期/证伪项→每类择一或同id更新→补齐空缺→按表排序。有变化才输出replace /传闻/条目，value必须包含完整10条，不能仅放新增消息，也不能写[]。未能读取旧数组时不要覆盖或标记完成，应先获得原始变量。
2. 完成推演后，在同一个JSONPatch的最后输出replace /传闻/上次世界推进时间点，value完整复制T。即使条目数组未变化、没有新消息，这一项也不能省略。
3. 禁止使用/传闻/0、/传闻/消息等错误路径。NPC镜头切换不更新根节点/时间和/地点。不另建“传闻更新”数组，不用正文说明代替实际操作。
