# 宗门经营初期设计蓝图

状态：初期设计蓝图，2026-10-15；2026-10-29 已在本地新增 `[宗门建设规则]` 及对应路由配置，加入材料建设判定。宗门新增名气，设施新增境界、品质，已同步变量结构与资产界面；经营自动结算及其他扩展仍为待定方案。

## 1. 目标与范围

在现有 RPG 玩法上，通过丰富固定资产，让玩家能够建立宗门、经营驻地，并从建设成果中获得成长感。

本轮已确定的方向：

- 以建筑和设施为主要载体，尽量复用现有资产结构，控制 MVU 上下文规模。
- 建设升级需要具体机缘，让宗门发展与玩家冒险互相推动。
- 同类建筑可以选择不同发展方向，形成宗门特色。
- 建筑之间可以配合，让资源获得更多用途。

初期不展开完整弟子名册、藏经目录、仓库明细、金融系统和产业链模拟。普通成员通过人员规模及设施描述体现，重要人物沿用现有关系系统。

核心循环：

> 冒险取得机缘 → 投入宗门设施 → 安排用途与发展方向 → 随时间获得成果 → 用成果支持冒险和下一轮建设。

## 2. 现有基础

已核对的文件：

- 卡仓库：`世界书/变量/[mvu_update]变量更新规则.yaml`
- 前端仓库：`src/修仙状态栏/schema.ts`
- 前端仓库：`src/修仙状态栏/pages/PageAssets.vue`
- 卡仓库：`世界书/[时间推进规则].txt`

当前固定资产支持：

| 层级 | 已有字段 | 可承载的内容 |
|---|---|---|
| 资产 | 类型、名气、人员规模、所在地、现状 | 宗门驻地及经营概况，名气用于宗门 |
| 资产 | 分配人物 | 在此工作或生活的重要 NPC |
| 设施 | 境界、品质 | 建设判定结果及效果、产出公式的 L/Q 来源 |
| 设施 | 效果 | 功能、专长、能力上限等简短描述 |
| 设施 | 每月产出 | 周期收益或产品 |
| 设施 | 上次收取日期 | 领取记录 |

当前资产类型限于宗门、店铺、洞府；宗门类资产在玩家成为宗主时加入。灵田、矿场、藏经阁等优先作为资产下的设施，不必各自成为顶层资产。

前端已经支持设施显示与编辑。时间推进规则允许描写玩家名下资产的变化，月度收益由 AI 按宗门建设规则结算。

注意：现有设施 schema 会提取已定义字段。未来若正式新增等级、项目等字段，需要同步调整 schema、变量规则和前端，不能只在提示词中添加字段名。

## 3. 宗门能力如何体现

以下是设计维度，初期不必全部成为独立数值。

| 方向 | 主要作用 | 设施载体举例 |
|---|---|---|
| 经营 | 灵石收支、原料产出、销售能力 | 灵田、矿场、商铺 |
| 情报 | 发现秘境、搜寻线索、获取其他势力消息 | 驻外据点、消息渠道 |
| 声望 | 为人所知、吸引弟子与合作机会 | 山门、接引院、论道场所 |
| 传承 | 教授功法、培养成员、提高培养上限 | 藏经阁、传功院 |
| 百艺 | 将原料加工为丹药、法器等成品 | 丹房、器坊、符室 |
| 防护 | 保护驻地、产业和成员 | 护山大阵、防御设施 |

声望还取决于玩家行为与宗门成果，不能仅靠建造山门增加。情报设施提供发现和调查的机会，实际消息仍受地点、人脉和行动影响。

初期可用设施能力和宗门现状表现这些方向。是否增加总评分，等实际游玩验证后再决定，避免同时维护建筑能力与同义数值。

## 4. 三个主要趣味来源

### 4.1 升级需要机缘

灵石承担建设成本，关键突破由具体资源、知识、人才或环境支撑。

| 设施 | 升级契机 | 升级后的变化 |
|---|---|---|
| 藏经阁 | 获得并整理更高境界的传承 | 能教授更高阶段的修行内容 |
| 丹房 | 引入地火、丹师或关键丹方 | 能炼制新种类或更高层次的丹药 |
| 灵田 | 改善灵脉、引入灵泉或特殊种植法 | 可种植新灵药，或提高现有产出 |
| 情报据点 | 建立当地关系、取得合作资格 | 开始获取某地域或某类事务的消息 |
| 护山大阵 | 获得阵图、阵材并完成布设 | 扩大范围或获得新的防护特性 |

升级提供明确的新能力。每次升级选取最相关的条件，不必套用统一的多项材料清单。

### 4.2 同类设施可以专精

发展方向先用一两条特性表达，不急于制作完整科技树。

- 藏经阁：广泛收录，适合不同灵根的弟子；或专精一脉，强化本门特色。
- 灵田：生产较低境界、品质的药材以增加数量；或生产同境界、同品质的稀有灵药。
- 丹房：供应日常修炼丹药；或集中承担少量珍贵丹药的炼制。
- 情报据点：熟悉遗迹秘境；或擅长商路消息、势力动向。
- 护山大阵：重防御、重隐蔽，或重灵气调理。

玩家选择影响可做的事情和产出结构，转向按改建规则投入灵石和材料。

### 4.3 设施之间配合

优先设计玩家容易理解的联系：

- 领取灵田药材 → 玩家亲手炼丹或出售。
- 情报据点发现遗迹 → 玩家探索 → 带回残篇 → 藏经阁完善传承。
- 领取矿场材料 → 玩家制作装备或改善防护设施。

设施月产物全额归玩家，玩家再决定用于制作、培养成员或出售。

组合收益可以体现为新增产品、降低采购需求或获得行动机会，不必全部采用百分比加成。

## 5. 首批设施建议

实施进展：`世界书/[宗门建设规则].txt` 已按生产、交易、研习、情报与接引、阵法整理效果示例，物资、灵石及名气统一记入每月产出。建设与结算由 AI 依据规则执行，尚未实现脚本自动经营结算。

本地已实现的建设流程：

- 建设前确定用途、规模、目标境界、负责人和建材；负责人境界须达到目标。
- 新建、升级、修复均收取建设费 `ceil(10^目标L×K)`，K 分别为 10、5、2。通过境界、灵石及建材检查后扣费扣料，再进行建造判定。
- 参考生产制作，以相关技艺、器具和材料能效对抗建造难度，按差值确定品质，再按最终境界与品质计算效果和产出。
- action_info 分为建设检查、素材与建造判定、建成效果与产出；展示所用公式的实际代入值。
- 建造成功即建成；失败消耗本次费用与材料，保留原设施及受损状态；修复成功恢复原状。
- 设施“概况”保存规模与投产日期，阵法另记灵气容量与攻击力，不占效果条数。门规记入资产现状；改建保留领取日期，旧期产物与新产量分段记录。
- 旧存档优先从“概况”提取境界、品质；无法辨识时境界显示“未定”、品质默认“凡”，保留原效果和产量。名气缺失时默认 0。

本地已确定的效果与产出：

- 辅助加成采用 `Z(a)=L×(1+Q)×a`，展示为 `${Z(a)}%`；普通加成 a=1～2，修行速度 a=0.5～1。技艺等先折算临时取值，参悟能效及修行速度进入对应规则的百分比加成。
- 阵法灵气容量 `floor(10^L×(2～6)×(1+Q))`，攻击力 `floor(10^L×(0～0.3)×(1+Q))`，非攻击阵法攻击力为0；基础数值存入概况，具体效果按凡/黄/玄1条、地/天2条生成。
- 物资月产量 `floor(10^设施L×(1+设施Q)/(10^产物L×(1+产物Q)))`；产物L、Q分别不高于设施L、Q，否则生产失败。同境界、同品质每月产1份，产出全额归玩家。
- 名气收支记入每月产出：每月 `±N` 或每次指定活动 `±3N`，其中 `N=floor((L+1)×(1+Q))`；名气最低为0。
- 商业月净收益 `floor(U×10^L×(1+Q)/100)`，U 为领取时所属宗门的名气。每月产出保留“数字×名气”，数字由 `10^L×(1+Q)/100` 算出；例如筑基初期凡品写“每月产出1×名气灵石（净收益，实收向下取整）”。
- 上次收取日期初始为建造时间。领取时按经过的完整月数×每月产出，将物资、灵石及名气入账；商业按领取前名气计算，随后更新收取日期为当前时间。
- 设施能力写入效果，产出规则写入每月产出，由 AI 在领取时更新变量。

以下为候选内容，不要求每个宗门全部具备。

| 设施 | 基本收益 | 玩家决策 | 可引出的冒险 |
|---|---|---|---|
| 灵田 | 灵药或出售收益 | 种什么、留用还是出售 | 寻找种苗、灵泉、种植传承 |
| 矿场 | 矿材或出售收益 | 开采方向、供应对象 | 探查矿脉、解决运输与开采困难 |
| 商铺 | 交易收益与销售渠道 | 销售宗门产品或经营采购 | 打通商路、寻找合作方 |
| 藏经阁 | 功法储备和教学能力 | 广收博采或专精一脉 | 寻访遗迹、交换传承、补全残篇 |
| 丹房／器坊 | 成品及生产辅助 | 选择产物与品质 | 招揽人才、寻找丹方与特殊材料 |
| 情报据点 | 定向消息与调查机会 | 关注地区和消息类别 | 搜寻秘境、核实传闻 |
| 接引院／论道场 | 招募和交流条件 | 招募方向、举办何种活动 | 接待来访、论道、宗门交流 |
| 护山大阵 | 驻地保护 | 防御、隐蔽或辅助修炼 | 寻找阵图、阵材与布阵者 |

建议最小体验先验证灵田、丹房、藏经阁，分别覆盖产出、加工、能力解锁；情报与防护随后扩展。

## 6. 藏经阁如何控制上下文

藏经阁记录馆藏能力、主要专长和少数特色传承，普通功法按类别概括。

示例：

> 木系与灵植传承，可教授至筑基；特色传承《青禾长生诀》；当前寻求结丹篇。

玩家亲自修习或剧情需要时，再展开相关功法。已展开的详细内容应沿用合适的现有载体，避免在资产中重复保存全文。

长期变量保留当前有效信息：

- 同类普通设施可按功能合并，具有不同用途或独有特点时再拆分。
- 建成后更新设施能力，建设经过交给历史总结。
- 普通成员概括为规模；重要负责人引用人物姓名。
- 不预先生成尚未拥有的设施，也不列出全部未来升级路线。
- 建筑说明控制在能力、特性、当前用途等必要信息内。

隐藏或折叠前端面板只影响显示，不等于减少送给模型的变量；上下文控制首先依靠记录范围。

## 7. 变量表达草案

第一阶段建议先利用设施的 `效果` 字典表达能力与专精。以下仅展示设施片段，沿用当前字段；示例内容与数值不作为正式平衡标准。

```yaml
设施:
  藏经阁:
    境界: 筑基初期
    品质: 玄
    效果:
      传承: 公开《青禾长生诀》的木系与灵植法门，篇章完整至筑基
    每月产出: 无
    上次收取日期: {年: 1, 月: 1, 日: 1, 时辰: 辰时} # 示例建造时间
  青溪灵田:
    境界: 炼气初期
    品质: 黄
    效果:
      培育辅助: 培育水木灵植时，培育技艺临时增加1.25%
    每月产出: 养气草，炼气初期、黄品，1株/月
    上次收取日期: {年: 1, 月: 1, 日: 1, 时辰: 辰时} # 示例建造时间
  丹房:
    境界: 炼气初期
    品质: 黄
    效果:
      炼丹辅助: 在此炼丹时，炼丹技艺临时增加1.25%
    每月产出: 养气丹，炼气初期、黄品，1枚/月
    上次收取日期: {年: 1, 月: 1, 日: 1, 时辰: 辰时} # 示例建造时间
```

这种表达适合先验证叙事与决策，但自由文本不等于可由程序精确计算的经济数据。

境界、品质现已成为独立字段；概况记录规模、投产时间及阵法基础数值。

## 8. 收支与时间推进

领取时按当前时间与上次收取日期之差计算完整月数，月产出乘以月数入账，并更新收取日期。物资产量按设施与产物的L/Q计算；商业按领取前名气计算；活动名气在活动完成时增减。

后续仍需验证：

1. 不同设施与产物境界、品质组合的月产量是否合适。
2. 物资首次结算以概况中的投产时间为起点，旧存档的缺失信息如何补全。
3. 收取、消耗与再投入的记录是否足够简洁。
4. 长期闭关如何处理停产、经营变化和资源消耗。
5. 多座设施的月度名气与商业收益是否便于结算。

世界推进优先呈现建设成果，以及少量值得玩家处理的新选择。例如药田成熟、传承整理完成、商会提出采购合作。事件应与设施用途和既有行动相关，也应有平稳经营、顺利成长的阶段。

## 9. 一次完整体验示例

1. 玩家成为宗主，宗门已有一处灵田，依靠出售普通药材维持运作。
2. 探索时获得丹方，并结识愿意合作的丹师。
3. 玩家建设丹房，选择修炼用丹药作为月产物。
4. 世界推进后，玩家领取灵田药材和丹房成品。
5. 外部商会提出采购，玩家选择留用或出售所得。
6. 增产需要提高设施境界与品质，由此形成寻找建材和营造图纸的新目标。

此过程主要更新设施能力、用途、成果和必要人物信息，无需展开全部生产人员与原料库存。

## 10. 分阶段完善

### 第一阶段：确定规则

- 确定首批设施、能力边界和发展方向。
- 确定采用明确结算、概括供给或混合方案。
- 确定等级含义：设施品质、规模与可支持修士境界如何区分。
- 用一座小宗门演练短期经营与长期闭关，评估信息量和决策是否有趣。

### 第二阶段：最小实现

- 优先复用固定资产与设施结构，补充相关世界书规则。
- 接入时间推进中的建设成果与经营变化。
- 必要的新字段同步修改变量规则、schema 和资产界面。
- 验证旧资产兼容、收益结算及闭关后的状态变化。

### 第三阶段：按体验扩展

- 增加情报据点、防护设施和宗门交流。
- 丰富少量建筑专精与协作关系。
- 根据实际需求加入升级展示、经营概览或定向委派。
- 独立能力数值、弟子培养和金融玩法保留为后续选项。

## 11. 下一轮优先讨论

1. 经营收益需要精确到什么程度？
2. 建筑成长用等级表达，还是直接用修行层次和功能表达？
3. 玩家更常主动领取成果，还是在世界推进后集中处理？
4. 首批是否用“灵田—丹房—藏经阁”验证完整循环？

后续每次完善优先解决一个问题，再更新本蓝图，逐步形成可以实施的规则。
