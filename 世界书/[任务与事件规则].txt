<rule name="任务与事件规则">
# 触发与定位
  - 本面板为<user>当前追踪的“进行中事项”，涵盖【委托任务】、【奇遇/突发事件】与【长线剧情事件】三大类。
  - 允许多个事项在 stat_data.历练 中并发共存（例如进行长线剧情的同时，并行接取与追踪宗门委托）。
  - 仅在委托明确成立、偶发事件爆发、长线剧情到达关键里程碑，或既有事项状态发生实质阶段跃迁时输出面板。
  - 闲谈传闻、线索提及、未经确认的口头请求，以及一轮即结的日常小互动严禁建卡。

# 并发与防误判铁律
  - 【命名空间与唯一性】：事项名称必须为纯中文短语（4~8字，如“残简之秘”、“百草采撷”），严禁包含任何标点符号。JSON Patch 路径严禁使用 ~1 转义。
  - 【长线剧情静默探索律】：模式三（长线剧情事件）由专属世界书条目驱动。在【初始开启】、【分支抉择】与【结局收束】之间属于自由探索期；玩家与NPC的自由交涉、观察、调息等日常互动，AI必须在正文中自由推演，**严禁每轮重复输出 <task_info>**，严禁在剧情现场把既有NPC/敌手当成新奇遇建立模式二面板。
  - 【同名定向更新律】：若正文推进的是既有事项，一切变动仅允许在 Patch 中定向更新该条目，绝不得另立新卡。

# 输出格式
  输出前以 <!-- ... --> 核对触发条件、分类模式及面板与变量的一致性。

  [模式一：委托任务]（有人托付、有明确交付与酬劳；经典契约制）
  <task_info>
    {任务名称}
    | 状态: [进行中|待结算] | 难度: [境界] |
    | 委托方: [人物或组织] | 截止时间: [YYYY年M月D日时辰|无] |
    | 目标: [一句话达成条件] |
    | 进展: [当前最新进展] |
    | 奖励: [具体奖励] |
    | 交付: [对象、地点与交付条件] |
  </task_info>

  [模式二：奇遇/突发事件/危机]（游历探索中偶发、突发险境与短线机缘；快进快出）
  <task_info>
    {事件名称}
    | 状态: [进行中|待平息] | 难度: [境界判定] |
    | 态势: [机缘|险境|异象|因果] | 紧迫: [时态倒计时/局势平缓/无] |
    | 牵涉: [现场涉及的人物、古修遗存或周边势力] |
    | 焦点: [当下的核心悬疑、对峙局面或破局矛盾] |
    | 进展: [当前最新异动] |
    | 祸福: [暗藏机缘与潜在凶险] |
  </task_info>

  [模式三：长线剧情/宿命事件]（专属世界书驱动·大纲里程碑式推进·统一紫色外观）
  <task_info>
    {事件名称}
    | 类别: 剧情 | 状态: [进行中|待抉择|待平息] | 难度: [境界判定] |
    | 幕次: [第一幕 | 第二幕 | 第三幕 | ... | 终幕] | 紧迫: [时态倒计时/局势平缓/无] |
    | 局势: [当前宏观背景与对峙局势] |
    | 契机: [当前等待触发的核心转折点，如：追兵破空/生死抉择/晨曦雨歇] |
    | 焦点: [核心矛盾与利益悬疑] |
    | 进展: [当前最新异动或里程碑总结] |
    | 牵涉: [现场涉及的核心人物、势力或古修遗存] |
  </task_info>

# 状态机协同规范
  - 【幕次统一规范】：长线剧情以纯数字幕号递进（第一幕、第二幕、第三幕...，最后一幕统称为终幕），严禁在幕次中拼接自定义副标题（如严禁写“第一幕·揭幕”），保持枚举规则通用规范。
  - 事项开启/推进：写入 stat_data.历练.{名称}，状态为 [进行中] 或 [待抉择]
  - 目标达成/局势收束：委托变更为 [待结算]，事件变更为 [待平息]
  - 交付领奖/事件完结/失败放弃：自 stat_data.历练 中彻底移除此条目（{ "op": "remove", "path": "/历练/{名称}" }），保持状态栏清爽。
