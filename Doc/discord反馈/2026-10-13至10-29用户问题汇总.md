## 优先处理的未解决问题

### P1-01 总结自动更换世界书，随后从头总结

**状态：未解决。** 10 月 23 日用户反馈大约每百楼出现新的总结世界书，累计 16 本；新书又从头总结，一次覆盖 0–772 楼，继而出现输入过长。用户否认主动改名。截图确实存在多本不同后缀的总结世界书；另一张截图显示当时已有绑定，不能据此证明整个过程中绑定始终正常。

- [约每百楼新建世界书](https://discord.com/channels/1380075940285124724/1497676115647397909/1563099915712864299)；[累计 16 本](https://discord.com/channels/1380075940285124724/1497676115647397909/1563100732020883537)；[从 0–772 楼总结](https://discord.com/channels/1380075940285124724/1497676115647397909/1563097875645202443)。
- [多本世界书截图](https://discord.com/channels/1380075940285124724/1497676115647397909/1563099849946169415)；[当前绑定与总结进度截图](https://discord.com/channels/1380075940285124724/1497676115647397909/1563100344328658944)；[用户否认改名](https://discord.com/channels/1380075940285124724/1497676115647397909/1563102323205738577)。

排查方向：本地绑定读取异常可能被当作“未绑定”，随后进入自动建书流程；这是代码层面的候选路径，尚未证明就是该用户的原因，也未发现可直接解释“每百楼”的固定阈值。应保留绑定读取失败、聊天切换、建书时的聊天 ID 和新旧书名，区分临时读取失败与真实未绑定。

### P1-02 额外 API 返回正文而非变量补丁

**状态：未解决；需与下一项区分。** 10 月 25 日截图中，变量更新请求返回了正常故事正文。返回文本明确采用“不更新变量，不输出 UpdateVariable”的要求，并将更新变量的任务当成提示词注入，最终导致 JSON Patch 解析失败。

- [返回正文及变量解析失败截图](https://discord.com/channels/1380075940285124724/1497676115647397909/1563585951454732382)。

这不是仅凭“换模型”即可解释的问题。优先检查额外 API 的最终请求是否混入正文预设的“不更新变量”分支、任务声明与输出格式是否冲突。需要该次变量请求的完整处理后提示词，而不只是主 API 提示词。

### P1-03 额外 API 被供应商拒绝，错误内容继续进入补丁解析

**状态：未解决／外部拒绝与错误处理共同涉及。** 10 月 27 日截图明确显示 `PROHIBITED_CONTENT` 和请求被拒绝；MVU 随后报告无效 JSON Patch。此前讨论中的路径配置猜测不能覆盖这张截图。28 日仍有新开局、换模型后无法更新变量的反馈，未见最终恢复确认。

- [拒绝与解析错误截图](https://discord.com/channels/1380075940285124724/1497676115647397909/1564453679363526696)；[新开局仍失败](https://discord.com/channels/1380075940285124724/1497676115647397909/1564891830380658699)；[换模型后仍未更新](https://discord.com/channels/1380075940285124724/1497676115647397909/1564898248026493070)；[作者确认截图属于通道拒绝](https://discord.com/channels/1380075940285124724/1497676115647397909/1564916009855361035)。

应将供应商错误直接显示为请求失败，避免只向用户报告补丁格式错误；其他模型的失败需要各自的响应证据，不能全部归为同一个原因。

**10 月 29 日本地修复进展：** 本卡 MVU 加载入口已增加请求错误检查，在其 `generate` / `generateRaw` 返回错误正文时，于补丁解析前中止并提示内容限制、鉴权、权限、限流、服务不可用或网络错误。正常补丁和手动停止保持原行为，已有模拟测试；尚未发布及用户复测。该检查不覆盖绕过酒馆助手生成接口的 MVU 原生直连路径，也不改变供应商的拒绝决定。

**状态：未解决，后续重复出现。** 10 月 16 日已有实际补丁向 `/任务/聚焦任务` 写入字符串、向 `/任务/已完成任务` 写入数组；作者当时表示后续更新处理。24 日用户仍反馈删除后再次出现，截图中这两个字段作为进行中任务展示。

- [原始补丁](https://discord.com/channels/1380075940285124724/1497676115647397909/1560644087944708178)；[作者表示后续处理](https://discord.com/channels/1380075940285124724/1497676115647397909/1560644964457648219)；[24 日仍重复出现](https://discord.com/channels/1380075940285124724/1497676115647397909/1563521452484075684)；[错误任务截图](https://discord.com/channels/1380075940285124724/1497676115647397909/1563521676912631831)。
