# 世界书接口与顺序审计

## 结论与此前说明的纠正

此工程世界书的 EJS 运行于 **ST-Prompt-Template**，不是酒馆助手脚本环境。此前将两者同名接口混为一谈的说明不正确；此前测试使用宽松的酒馆助手式模拟，也未能发现真实兼容性问题。

本轮直接读取并运行本机安装的 `ST-Prompt-Template/src/function/chat.ts`，确认：

| 调用 | 本机 EJS 插件的行为 | 处理 |
|---|---|---|
| `getChatMessages(10)` | `slice(0, 10)`，开头十条字符串 | 最近聊天检测改为 `-10` |
| `getChatMessages(-10)` | `slice(-10)`，末尾十条字符串 | 世界书正确用法 |
| `getChatMessages('起-止')` | 不是该插件的合法范围形式，本机返回空数组 | 按原意改为 `-4`、`-5`、`-6` 等负数窗口 |
| `getChatMessages(-1, {hide_state:'all'})` | 第二参数不是该插件的合法类型，本机返回空数组 | 移除酒馆助手式选项 |
| `.map(m => m.message)` | 误把返回的字符串当消息对象，得到空内容 | 对字符串直接 `join('\n')` |

上表只针对 EJS 插件。`预设/本格修仙/脚本/隐藏历史用户楼层.js` 与 `脚本/【本格修仙】总结.js` 是酒馆助手脚本，其字符串范围和选项属于另一套接口，保持不变。不得在两个运行环境之间机械统一 API。相邻前端仓库 `src` 未检出该接口调用，无需为此改动前端。

插件的负数窗口不等同于“过滤隐藏楼层后的最近十条”，不再宣称自动执行 `hide_state` 过滤。接口参考：[官方文档](https://github.com/zonde306/ST-Prompt-Template/blob/master/docs/reference.md)；实际正负数行为以本机源码与运行验证为准。

## 修复范围

修复 183 份含消息读取的世界书文件，包含凡界人物、凡界和灵界总览、灵界人物、生命种族、技艺、物品功法生成、事件及事件模板、相关情境条目。修改限于消息读取代码，未借接口修复重写凡界人设正文。

审计对象为当前工程 `世界书/` 下的全部条目与主 YAML；历史备份、外来参考角色卡不是当前加载源，未改写其快照内容。本地 PNG 导出卡也不会因为源文件修改自动更新，导入前需重新打包。

同步修复灵界人物生成器、人物结构文档、事件测试和总览测试，防止重新生成错误接口。灵界第二版人物深写另行分批完成，共 256 人、116 份人物文件；文风经过小批次抽查与定点回修，不把接口测试通过视为文学质量合格。

## 插入顺序

`本格修仙.yaml` 当前共有 160 个人物条目：44 份凡界、116 份灵界。全部使用 `顺序: 200`，位于人物包装起点 151 与终点 250 之间。本轮没有发现需要改动的实际人物顺序；过时的 `56` 只是旧文档约定，不应恢复到工程中，也不能把其他类型条目的顺序一律改成 200。
