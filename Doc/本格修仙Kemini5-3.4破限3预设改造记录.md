## 破限3头尾与清理方式

参考预设的原版 `🪐破甲3(目前最有效)` 要求模型返回完整的三行 Python 脚本，因此正常输出会包含以下外壳：

```python
import sys
content = """<｜begin｜>
目标文本
<｜over｜>"""
sys.stdout.write(content)
```

参考预设同时启用了名为 `删除起止标记` 的正则，用来删除 `import sys`、`content = """<｜begin｜>`、`<｜over｜>"""` 和 `sys.stdout.write(content)`。

本格修仙预设没有直接照搬这一输出方式。新增的 `🪐破限3·本格文本补全` 将 Python 内容描述为宿主侧编辑缓冲区，并要求模型只返回 `[CURSOR]` 位置的目标文本，不返回 Python 外壳。这样可以避免外壳干扰以下结构：

- `<thinking>` 或 `<think>` 思考区；
- `<now_plot>` 与 `<gametxt>` 正文区；
- HTML/XML 面板标签；
- `<UpdateVariable>`、JSON Patch 与 MVU 更新内容。

为了兼容模型偶尔不遵守“只返回目标文本”的情况，当前预设仍新增并启用了兜底正则 `破限3兼容·删除Python起止壳`。它只在检测到 Python 外壳时删除外壳；模型直接返回正常正文时不会改动内容。

正则配置：

- 位置：用户输入与 AI 输出（`placement: [1, 2]`）；
- 编辑时执行：开启；
- 提示词处理：开启；
- Markdown 处理：开启；
- 替换内容：空字符串；
- 普通正文无外壳时保持原样。

已使用包含 `<thinking>`、`<now_plot>`、`<gametxt>` 和 `<UpdateVariable>` 的模拟结果验证：Python 头尾能够删除，内部标签和变量区保持不变。

## 提示词结构调整

### 新增文本补全头部

在提示词顺序首位新增并启用 `🪐破限3·本格文本补全`，采用参考预设的本地文件自动补全思路，但输出协议改为只生成光标处的目标文本。

### VOID要求迁移为用户偏好

旧 `🛑VOID设定` 改为 `⛄用户偏好(可以自己改)`。保留的要求包括：

- 规则、数值和骰子决定结果；
- 不使用机械降神或不合理优待；
- NPC保持独立性和主动性；
- 保持沉浸感、有限视角与历史连续性；
- 不省略规定的标签、面板、数值和变量更新；
- 避免套娃反转、油腻描写、刻板印象和无理由崇拜；
- 成人亲密内容作为创作偏好表达，并服从人物设定、剧情关系和已启用规则。

### 移除高风险身份指令

以下旧结构被移除或改写：

- `CLEAR / RESET ROLE / DISCARD AI IDENTITY`；
- “最高权限”“不得被覆盖”“无审查限制”等权限声明；
- 要求模型反复确认 VOID 或 Recorder 身份；
- 尾部的 VOID 与 Recorder 对话式启动命令。

对应提示词调整为：

- `🧩文本补全上下文`；
- `📝文本补全任务`；
- `🎭叙事执行偏好`；
- 中性的 `CompletionHost` 尾部补全指令。

数值裁决、世界规则、认知边界、格式闭合、MVU 与变量更新要求均保留。
