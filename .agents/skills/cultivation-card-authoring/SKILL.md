# 本格修仙编写与维护

从所在工程向上定位同时含 `本格修仙.yaml` 和 `Doc/README.md` 的卡片源码根目录。先读该索引的“按任务读取”和“材料效力”，只加载任务相关文档与数据行。前端任务同时读相邻前端工程的开发说明。

## 开始修改前

- 确认用户最新选择、维护源、生成物与已有修改；讨论和预览不等于实施授权。
- 世界书／预设先读提示词规范；EJS修改再读变量写作经验与接口顺序审计；人物、宗门、秘境、开局按索引核对对应底表和既有条目。
- 剧情修改读事件规范、逐幕条件表及最新按幕验证报告。历史报告用于追溯，不把中间方案恢复成当前规则。
- 同步或构建测试卡前读完整测试卡同步流程与组件版本说明。发布另读上线流程，并遵守本次授权范围。

## 当前剧情约定

- 南疆一幕是一段事件：进入条件、素材、玩家决定边界、完成／退出标志、下一幕条件。问询、犹豫、探索不拆成细碎阶段。不得借精简重写情节、奖励或门槛。
- 脚本守专属开局资格、暂停、合法幕次、防重开及必要硬门槛；AI依据真实正文判断开启时机、退出和分支。资格达标不等于玩家已接受、移动或获胜。
- 各线进度在 `历练[剧情名]` 分别保存；`事件`聚焦只作当前索引。阶段保存精确幕次，`本幕进行中`区分演出与幕间等待，分支保存实际结果。
- 当前幕优先，每轮最多开启一幕，结束本幕后不在同轮开启下一幕。幕结束释放聚焦、保留进度与推进线索；整线真正结束／中断才归档移除。
- 内部自动／手动／暂停对应自由／指定剧情／无剧情。暂停只由玩家解除，AI及同步不得覆盖。切换不清空各线进度，不展示未发现剧情。
- 新幕实际开启时正文输出一次完整 `<task_info>`，后续交互不重复；祖窟首幕由开局确认页与初始化同源展示，正文不重复插卡。面板、正文、MVU持久化分别核对。
- 保留普通变量流程与明确状态事实，不恢复逐字段强制Patch、固定第五选项、剧情前缀识别、模式二卡片或隐藏回执结算。委托类别显式写委托，普通探索不另造剧情卡。
- 公共运行入口只维护一份；通用核心、地区条件、注册表各司其职，世界书按需加载本幕。规模小时不为每个概念拆短文件。新增地区按注册接入，不复制调度或全量剧情进常驻提示。
- 日常集合一轮一个小事件，保留玩家回应边界；采用当前集合的完成机制，不直接套用旧“一轮出现即完成”范例。其他地区保留现状。

## 验证与交付

先做与改动相关的离线条件、EJS组合渲染及构建。EJS局部声明隔离作用域，检查同条目重复拼接。提示长度比较渲染结果，不用源码行数代替。

测试使用完整独立测试卡与配套预设，沿用 `tavern_sync.mjs` 和现有资源加载，不新造内嵌包或用裁剪卡代替。同步后回读角色绑定、世界书、脚本、正则、预设、前端实际资源及启动版本；推送成功或HTTP 200不足以证明内容正确。条目数、版本号取当前配置，不永久锁死历史数字。

默认交互式实测：助手检查规则并建议一条自然输入，用户发送，助手结合原始正文、标签、真实变量与显示结果定位；未经当次明确要求不自动发送、重生成或调用模型。不伪造助手正文、阶段或完成记录作为实聊证据。新初始化用新聊天，旧聊天重生成不会替换旧开局数据。先检查确认页和初始记录，再消耗模型调用。

UI采用既有组件与风格；历练卡所有宽度均单列，详情各占一行。区分样例预览、标签生成、变量保存、实际显示、刷新持久化和整线通过。报告准确列出本轮检查、阻断及未验证项，不累计旧测试数冒充本轮结果。

测试同步不授权正式发布、提交或推送Git；不改旧聊天或学习副本。文档按Doc既有分类维护，数据表保持路径、列结构和编码。

经验出处：[对话复盘](../../../Doc/03-专项重构与验证/精简剧情规则对话复盘.md)。
