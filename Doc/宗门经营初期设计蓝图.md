# 宗门经营初期设计蓝图

状态：讨论稿，2026-10-15。用于后续逐步完善，本文件不代表已经修改变量、提示词或前端。

## 1. 目标与范围

在现有 RPG 玩法上，通过丰富固定资产，让玩家能够建立宗门、经营驻地，并从建设成果中获得成长感。

本轮已确定的方向：

- 以建筑和设施为主要载体，尽量复用现有资产结构，控制 MVU 上下文规模。
- 建设升级需要具体机缘，让宗门发展与玩家冒险互相推动。
- 同类建筑可以选择不同发展方向，形成宗门特色。
- 建筑之间可以配合，让资源获得更多用途。

初期不展开完整弟子名册、藏经目录、仓库明细、金融系统和产业链模拟。普通成员通过人员规模及设施描述体现，重要人物沿用现有关系系统。

核心循环：

> 冒险取得机缘 → 投入宗门设施 → 安排用途与发展方向 → 随时间获得成果 → 用成果支持冒险和下一轮建设。

## 2. 现有基础

已核对的文件：

- 卡仓库：`世界书/变量/[mvu_update]变量更新规则.yaml`
- 前端仓库：`src/修仙状态栏/schema.ts`
- 前端仓库：`src/修仙状态栏/pages/PageAssets.vue`
- 卡仓库：`世界书/[时间推进规则].txt`

当前固定资产支持：

| 层级 | 已有字段 | 可承载的内容 |
|---|---|---|
| 资产 | 类型、人员规模、所在地、现状 | 宗门驻地及经营概况 |
| 资产 | 分配人物 | 在此工作或生活的重要 NPC |
| 设施 | 效果 | 功能、专长、能力上限等简短描述 |
| 设施 | 每月产出 | 周期收益或产品 |
| 设施 | 上次收取日期 | 领取记录 |

当前资产类型限于宗门、店铺、洞府；宗门类资产在玩家成为宗主时加入。灵田、矿场、藏经阁等优先作为资产下的设施，不必各自成为顶层资产。

前端已经支持设施显示与编辑。时间推进规则也允许描写玩家名下资产的变化，可以作为经营成果的叙事入口；具体结算能力仍需另行设计。

注意：现有设施 schema 会提取已定义字段。未来若正式新增等级、项目等字段，需要同步调整 schema、变量规则和前端，不能只在提示词中添加字段名。

## 3. 宗门能力如何体现

以下是设计维度，初期不必全部成为独立数值。

| 方向 | 主要作用 | 设施载体举例 |
|---|---|---|
| 经营 | 灵石收支、原料产出、销售能力 | 灵田、矿场、商铺 |
| 情报 | 发现秘境、搜寻线索、获取其他势力消息 | 驻外据点、消息渠道 |
| 声望 | 为人所知、吸引弟子与合作机会 | 山门、接引院、论道场所 |
| 传承 | 教授功法、培养成员、提高培养上限 | 藏经阁、传功院 |
| 百艺 | 将原料加工为丹药、法器等成品 | 丹房、器坊、符室 |
| 防护 | 保护驻地、产业和成员 | 护山大阵、防御设施 |

声望还取决于玩家行为与宗门成果，不能仅靠建造山门增加。情报设施提供发现和调查的机会，实际消息仍受地点、人脉和行动影响。

初期可用设施能力和宗门现状表现这些方向。是否增加总评分，等实际游玩验证后再决定，避免同时维护建筑能力与同义数值。

## 4. 三个主要趣味来源

### 4.1 升级需要机缘

灵石承担建设成本，关键突破由具体资源、知识、人才或环境支撑。

| 设施 | 升级契机 | 升级后的变化 |
|---|---|---|
| 藏经阁 | 获得并整理更高境界的传承 | 能教授更高阶段的修行内容 |
| 丹房 | 引入地火、丹师或关键丹方 | 能炼制新种类或更高层次的丹药 |
| 灵田 | 改善灵脉、引入灵泉或特殊种植法 | 可种植新灵药，或提高现有产出 |
| 情报据点 | 建立当地关系、取得合作资格 | 开始获取某地域或某类事务的消息 |
| 护山大阵 | 获得阵图、阵材并完成布设 | 扩大范围或获得新的防护特性 |

升级提供明确的新能力。每次升级选取最相关的条件，不必套用统一的多项材料清单。

### 4.2 同类设施可以专精

发展方向先用一两条特性表达，不急于制作完整科技树。

- 藏经阁：广泛收录，适合不同灵根的弟子；或专精一脉，强化本门特色。
- 灵田：生产常用药材，收益稳定；或培育稀有灵药，周期长但价值高。
- 丹房：供应日常修炼丹药；或集中承担少量珍贵丹药的炼制。
- 情报据点：熟悉遗迹秘境；或擅长商路消息、势力动向。
- 护山大阵：重防御、重隐蔽，或重灵气调理。

玩家选择影响可做的事情和产出结构。转向可以消耗改建时间与资源，具体规则待定。

### 4.3 设施之间配合

优先设计玩家容易理解的联系：

- 灵田供药 → 丹房炼丹 → 自用、培养成员或交由商铺出售。
- 情报据点发现遗迹 → 玩家探索 → 带回残篇 → 藏经阁完善传承。
- 矿场供材 → 器坊制造 → 装备成员或改善防护设施。

初期只记录当前启用的用途。原料转入加工后，应体现其去向，收益估算避免同时计算原料出售和成品出售。

组合收益可以体现为新增产品、降低采购需求或获得行动机会，不必全部采用百分比加成。

## 5. 首批设施建议

以下为候选内容，不要求每个宗门全部具备。

| 设施 | 基本收益 | 玩家决策 | 可引出的冒险 |
|---|---|---|---|
| 灵田 | 灵药或出售收益 | 种什么、留用还是出售 | 寻找种苗、灵泉、种植传承 |
| 矿场 | 矿材或出售收益 | 开采方向、供应对象 | 探查矿脉、解决运输与开采困难 |
| 商铺 | 交易收益与销售渠道 | 销售宗门产品或经营采购 | 打通商路、寻找合作方 |
| 藏经阁 | 功法储备和教学能力 | 广收博采或专精一脉 | 寻访遗迹、交换传承、补全残篇 |
| 丹房／器坊 | 加工成品 | 内部供给或对外委托 | 招揽人才、寻找丹方与特殊材料 |
| 情报据点 | 定向消息与调查机会 | 关注地区和消息类别 | 搜寻秘境、核实传闻 |
| 接引院／论道场 | 招募和交流条件 | 招募方向、举办何种活动 | 接待来访、论道、宗门交流 |
| 护山大阵 | 驻地保护 | 防御、隐蔽或辅助修炼 | 寻找阵图、阵材与布阵者 |

建议最小体验先验证灵田、丹房、藏经阁，分别覆盖产出、加工、能力解锁；情报与防护随后扩展。

## 6. 藏经阁如何控制上下文

藏经阁记录馆藏能力、主要专长和少数特色传承，普通功法按类别概括。

示例：

> 木系与灵植传承，可教授至筑基；特色传承《青禾长生诀》；当前寻求结丹篇。

玩家亲自修习或剧情需要时，再展开相关功法。已展开的详细内容应沿用合适的现有载体，避免在资产中重复保存全文。

长期变量保留当前有效信息：

- 同类普通设施可按功能合并，具有不同用途或独有特点时再拆分。
- 完成建设后更新设施能力，已结束的施工过程交给历史总结。
- 普通成员概括为规模；重要负责人引用人物姓名。
- 不预先生成尚未拥有的设施，也不列出全部未来升级路线。
- 建筑说明控制在能力、特性、当前用途等必要信息内。

隐藏或折叠前端面板只影响显示，不等于减少送给模型的变量；上下文控制首先依靠记录范围。

## 7. 变量表达草案

第一阶段建议先利用设施的 `效果` 字典表达能力与专精。以下仅展示设施片段，沿用当前字段；示例内容与数值不作为正式平衡标准。

```yaml
设施:
  藏经阁:
    效果:
      传承: 木系与灵植法门，可教授至筑基
      特色: 藏有《青禾长生诀》，尚缺结丹篇
    每月产出: 无
    上次收取日期: null
  青溪灵田:
    效果:
      专长: 适宜水木灵植
      用途: 药材供丹房炼制养气丹
    每月产出: 养气丹常用药材一批
    上次收取日期: null
  丹房:
    效果:
      能力: 炼制炼气期常用丹药
      用途: 使用灵田药材，成丹供门人修炼
    每月产出: 养气丹十瓶，需足量药材
    上次收取日期: null
```

这种表达适合先验证叙事与决策，但自由文本不等于可由程序精确计算的经济数据。

后续若需要稳定显示等级、升级进度或自动结算，再增加必要的结构化字段。届时将旧描述中的对应信息迁入字段，避免两处维护同一事实。

## 8. 收支与时间推进：待定方案

此前尚未确定收益精度，保留两种方案：

| 方案 | 方式 | 适用体验 |
|---|---|---|
| 明确结算 | 记录周期产出、开销，按经过时间结算 | 经营收益清楚，数据和规则较多 |
| 概括供给 | 记录可提供的资源层次，领取或重大事件时具体结算 | 上下文较少，偏重剧情和重大决策 |

可优先试验混合方案：基础经营以简短净收益描述，稀有物品和专门委托按项目处理；固定与弹性产出的边界仍需讨论。

实际实现前，需要明确：

1. 产出何时入账：时间推进、主动领取，还是其他时点。
2. 首次结算从哪天开始：当前“上次收取日期”为 null，不能单独确定投产日期。
3. 收取、消耗与再投入如何区分：当前领取日期不等于完整结算记录。
4. 长期闭关如何处理停产、经营变化和资源消耗。
5. 灵石归玩家直接持有，还是保留少量宗门运营资金；初期尽量避免完整公私双账本。

世界推进优先呈现建设成果，以及少量值得玩家处理的新选择。例如药田成熟、传承整理完成、商会提出采购合作。事件应与设施用途和既有行动相关，也应有平稳经营、顺利成长的阶段。

## 9. 一次完整体验示例

1. 玩家成为宗主，宗门已有一处灵田，依靠出售普通药材维持运作。
2. 探索时获得丹方，并结识愿意合作的丹师。
3. 玩家建设丹房，将部分药材改为内部供应，选择优先炼制修炼用丹药。
4. 世界推进后，丹房完成生产，成员获得供给；玩家也得到可领取的成果。
5. 外部商会提出采购，玩家选择维持内部培养，或扩大生产以增加收入。
6. 扩产需要改善灵田或寻找稳定原料来源，由此形成下一轮目标。

此过程主要更新设施能力、用途、成果和必要人物信息，无需展开全部生产人员与原料库存。

## 10. 分阶段完善

### 第一阶段：确定规则

- 确定首批设施、能力边界和发展方向。
- 确定采用明确结算、概括供给或混合方案。
- 确定等级含义：设施品质、规模与可支持修士境界如何区分。
- 用一座小宗门演练短期经营与长期闭关，评估信息量和决策是否有趣。

### 第二阶段：最小实现

- 优先复用固定资产与设施结构，补充相关世界书规则。
- 接入时间推进中的建设成果与经营变化。
- 必要的新字段同步修改变量规则、schema 和资产界面。
- 验证旧资产兼容、收益结算及闭关后的状态变化。

### 第三阶段：按体验扩展

- 增加情报据点、防护设施和宗门交流。
- 丰富少量建筑专精与协作关系。
- 根据实际需求加入升级展示、经营概览或定向委派。
- 独立能力数值、弟子培养和金融玩法保留为后续选项。

## 11. 下一轮优先讨论

1. 经营收益需要精确到什么程度？
2. 建筑成长用等级表达，还是直接用修行层次和功能表达？
3. 玩家更常主动领取成果，还是在世界推进后集中处理？
4. 首批是否用“灵田—丹房—藏经阁”验证完整循环？

后续每次完善优先解决一个问题，再更新本蓝图，逐步形成可以实施的规则。
