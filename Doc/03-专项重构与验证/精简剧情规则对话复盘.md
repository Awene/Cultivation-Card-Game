# 精简剧情规则对话复盘

来源：Codex聊天 `01a17907-fb67-7f62-a0ea-eedc36dc5c00`（精简剧情规则与模式代码）。2026-10-31通过read_thread逐页读取全部49个回合的可返回内容；工具记录用于追溯，不视为当前状态证据。

## 设计收敛

1. 起点是减少常驻提示：移除模式二，委托与剧情保留共享展示字段；剧情面板由生效世界书提供，固定第五选项和剧情前缀样式删除。
2. 变量不能随提示一起删光：显示卡片不代表保存状态，必须保留精确阶段、实际分支、奖励事实与归档依据。
3. 多线进度从单一事件指针分离到各线历练，当前聚焦不再占住所有未来剧情。等待下一境界应释放镜头。
4. 公共逻辑先被重复生成进多条书，后收敛为统一运行入口、地区条件与注册；文件数按职责和规模控制。
5. 最终用户否定初醒／探索／待回应等细碎长线状态，确认为一幕一段事件。脚本守硬条件，AI判断叙事事实；以最新按幕方案取代此前严格关键词仲裁。

## 失败与有效修正

| 观察到的问题 | 可复用的处理 |
|---|---|
| 缺面板被笼统归为前端失败 | 分查原始标签、解析入口、类别、历练完整字段与资源版本 |
| 正文嵌套标签被截断 | 用实际包装组合检查捕获内容，不只测单层标签 |
| EJS重复声明 | 局部块隔离，并验证重复拼接编译 |
| 祖窟首幕重复发卡或物品 | 开局确认与初始化使用同源数据，后续正常变量结算 |
| 任务被记账模型写成剧情 | 检查显式类别和变量更新依据，不靠字段猜类别 |
| 旧聊天重生成仍使用旧开局 | 新初始化在完整测试卡新聊天验证，保留旧聊天 |
| 临时裁剪卡与额外内嵌构建混淆基准 | 使用完整独立测试卡、原同步工具与原加载方式 |
| 推送完成但绑定仍旧 | 回读安装后的世界书绑定与内容、脚本、正则和资源 |
| 自动多轮测试消耗大且用户看不到 | 改为助手建议输入、用户发送、依据反馈修正 |
| UI擅自重做布局不合预期 | 先渲染原主面板，再在既有布局讨论和修改 |
