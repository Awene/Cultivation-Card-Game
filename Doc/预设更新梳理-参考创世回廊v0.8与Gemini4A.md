## P0：接入 Gemini 4A 前应核对／修复

### 1. 实际连接通道的型号识别

本地 `SillyTavern-1.16.0/src/endpoints/backends/chat-completions.js:463` 的 `isThinkingConfigModel` 只匹配部分 Gemini 2.5 和 `gemini-3-(flash|pro)` 命名。`gemini-4-argon` 不匹配；约第 531 行只有匹配时才写入 `generationConfig.thinkingConfig`。

因此在当前原生 Google 分支中，仅把预设推理强度改为 low，不足以保证它被发送。后续应连同 budget/level 映射函数一起核验，不能只增加一个型号正则就算完成。

若实际使用 OpenAI 兼容或中转通道，应检查该通道最终发送的 reasoning_effort 与服务端映射，不能直接套用以上原生分支结论。

### 2. 上下文和输出上限

本卡上下文设置为 2,000,000、最大回复为 60,000；参考为 2,000,000／50,000。参考的上下文数值也不能直接用于 4A。

官方模型页说明 4A 的输入、思考、输出共享 1,048,576 token。按这个总量给输入和输出留余量；本卡已有 60,000 输出上限不必仅为升级而提高。还应核对酒馆／中转如何计算上下文余量。

### 3. 思考与采样配置

4A 使用 low、medium、high。建议以 low 作为候选测试档，与 medium 对比战斗、突破、生产等复杂规则场景后选定。本卡的“请求思维链=false”不能被理解为关闭模型原生思考。

官方迁移说明要求移除 temperature、top_p、top_k；4A 会忽略这些采样参数。应在该模型的请求层处理，不要为此删除其他模型仍需使用的全局参数。

如连接配置使用显式缓存，还要检查并移除 4A 不支持的 cached_content；没有使用则无需增加相关功能。

### 4. 保证实际请求尾部合法

保留非空 user 收尾的默认策略，禁用不受支持的 assistant/model 预填充。检查普通生成、重生成、续写、空输入及特殊模式，避免酒馆自动追加尾巴。

当前 Gemini 条目已有 user 角色和 no-trans 分隔，不需要因新增 4A 就重新启用旧 3.1P 分支。验证对象是宏展开、kemini 合并和后端转换后的请求，而非 YAML 的角色标签。

## P1：本卡预设文字更新建议

### 5. 头部简化与尾部同步

涉及 `🪐开头.txt`、`🧩文本补全上下文.txt`、`⚓️尾部.txt`。

可以借鉴新版参考脱离模拟 Python 执行环境的做法，改成明确的修仙世界叙事与规则裁决任务。保留当前规则优先级、输入尝试核验、有限认知、变量模式和 output_contract。若移除模拟补全包装，必须一并整理 CURSOR、TARGET_TEXT、Completion Protocol 等依赖；不能只换头部一段。

已有 Python 起止壳清理正则可作为旧历史兼容保留，不必同步删除。是否改善输出质量需通过相同场景对照，不能由参考作者换了写法便认定更强。

### 6. 保留七步短检查，简化 Gemini 起始规则

保留中文七步、Claude 英文七步，以及本卡的路由规则过滤、全局检查与局部判定分工。

当前 Gemini 入口含“若先产生 think，只输出 Complete. 再进入 thinking”的兼容措辞。建议评估改为直接要求正文输出以指定 thinking 段开始，不再试图用可见标签控制原生推理。它是提示词清理建议，不是接口成功所必需的修改。

不要迁移参考的三次 draft／正文循环，否则会与本卡仅一对 now_plot、局部面板位置和末尾变量更新约束发生冲突。

### 7. 模型入口维持轻量差异

Gemini 3.8F 与 4A 可以先共用一套非预填充文字入口，连接配置分别管理型号、思考档位和限制；仅在实测出现明确差异时再拆文字分支。Claude 保留英文短检查。若继续完成四家支持，GLM 仍需单独补配置，不能因参考是通用预设就视为已支持。

当前尾部使用“不是 Gemini 且不是 Deepseek 就走英文”的条件；新增 GLM 时应改为明确判断 Claude，避免 GLM 意外进入英文分支。

### 8. 历史清理与显示正则

当前显示正则主要覆盖 think/thinking，与现有协议一致。维持标签无需为参考的 draft 扩展正则。若未来统一标签，应同步修改入口、COT、显示正则、历史过滤、总结读取与预览。

核验历史回填时排除检查段而保留正文事实、摘要与所需变量信息。不要复制参考按词表删除历史正文的正则；本卡的装备、招式、承诺与判定事实需要准确保留。

## P2：可选写作改进

- 借鉴“同一人格特征通过不同动作表现”，减少每场重复口头禅和道具动作。
- 把素材排重做成短检查中的简短提醒，不增加第二套长链。
- 人物主动性以本卡利益、认知、关系和规则为边界，不复制“即时反噬”式硬性惩罚。
- 不复制固定 7:3 人格配比、每次强制换新素材、无条件主动翻脸等要求；它们可能破坏持续设定。
- 保留本卡的变量协议，不替换为参考的 update/update_analysis/json_patch 标签。

## 不整包移植参考脚本的具体原因

参考启用脚本约 142,017 字符，涵盖多种输入和输出传输方式，绝非单一模型开关。合成工具传输会让完整回复通过 `output_everything_here` 的参数返回，再转换为文本；不能把“反截断”名称理解为保证服务器不会截断输出。

本卡已有 kemini 消息合并、Unicode 转码、MVU 核验和路由流程。参考与本卡 Unicode 脚本还复用了 `unicode-floor-interceptor-panel` 等 DOM 标识，尽管全局 API 名不同，仍有界面冲突风险。若未来需要某项功能，应单独移植并验证事件顺序与工具调用行为。

## 后续验收范围

1. 渲染测试：各模型入口、主／额外变量模式、路由开关组合；只输出一套短检查，无残留宏或失配标签。
2. 请求检查：最终角色顺序、末尾非空 user、无意外 prefill、4A 思考参数确实发出、上下文预算合法。
3. 场景回归：日常、非战斗检定、战斗、生产、突破、重生成与续写；检查局部面板、骰子消费和变量只结算一次。
4. 原生思考与正文分离：隐藏思考展示不影响短检查和正文解析，主／额外 API 的变量行为保持正确。

此前短链测试只证明模板层组合可渲染，不等于上述真实模型兼容性已经通过。
