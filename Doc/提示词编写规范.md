# 提示词编写规范

目标：让叙事模型以尽量少的文本获得准确、可执行的设定与规则。

## 1. 区分程序与提示词

- EJS 在生成提示词时执行；叙事模型接收渲染结果，不接收随机池、筛选代码和程序注释。
- 条件判断、已知人物筛选、地点匹配、随机抽取交给 EJS；只输出当前需要的内容。
- 不向叙事模型解释“候选每次求值刷新”“刷新不重置人物”“本段是否加载”等实现过程。
- EJS 源码变短不等于输入 token 减少；以渲染结果衡量提示词开销。
- EJS 局部声明用块级作用域隔离，具体见《EJS变量写作经验.md》。

## 2. 一条信息只承担一个职责

- 总览提供大陆概况、公共生活、人物名册和地图；人物条目负责具体人物设定。
- 区分作者知道、叙事模型知道与角色知道。秘闻确需限制时，写清谁知道及获知条件，不反复声明“不可全知”。
- 已知人物不反复生成初见资料；按项目现有触发条件输出相应内容，不凭空增加展示档位。
- 不重复其他已激活条目的设定、公式或关系说明；引用应指向实际可用的规则。

## 3. 精简正文

- 优先写事实、条件、动作、结果。删除开场解释、总结复述、同义叠加和无作用的兜底。
- 删除对程序执行过程的防御性声明；保留会实际影响叙事、知识边界或解析结果的限制。
- 不额外添加年龄确认、死亡讨论、例外制度或角色关系。修订表达不等于扩建设定。
- 示例只在能消除歧义时保留；避免规则、示例、模板三处重复同一要求。
- 不为省字改变条件、取值范围、公式优先级、字段层级或输出位置。

## 4. 按内容选择形式

- 设定、历史、风俗用短句；不要把自然语言事实强行包装成程序。
- 流程与分支用简短中文写清触发条件、处理顺序和输出；计算直接给出公式。
- 区间写清范围，公式保留括号；系数沿用原规则，不自行补出数值。
- 不要求模型照抄流程或输出冗长思考。需要核对时只要求代入算式、结果或数量。
- 表达形式以实际生成效果为准，同时比较渲染后的 token 消耗。

## 5. 保持输出接口

- 区分“生成逻辑”与“最终面板”。改写流程时保留标签、YAML 键名、嵌套、类型和数组格式。
- 统一已有字段命名，不为文风新增同义字段。
- 填写指引与占位符不作为面板内容输出；必要格式约束集中声明一次。
- 原文若有冲突、未定义系数或缺失字段，单独记录待确认，不在格式改写中暗改规则。

## 6. 地图与图例

- 沿用凡界的 `graph TD` 与简短“地图阅读”结构。
- 实线表示相邻或常用通路，虚线表示标明方式的特殊通路；箭头用于明确方向，如水流。
- 仅补充图中无法直接表达的地形阻隔、水流和换乘关系。不复述节点名称和大陆概述。
- 同类地图统一符号含义；特殊连线在本图说明。无固定地理结构的地区不强加固定地图。
