# Prime 1.18 / 通用版 v1.0.0 与本格预设更新对照

核对日期：2026-11-04。参考本地 `Prime-1.18.json`、`v1.0.0.json`、`命定4.3.4.png`，旧 Prime 1.11 从 Git 已提交版本读取。未恢复用户已删除的参考文件。

## 本次已修改

### 1. 修正末尾噪声的标签

之前的最终输出格式已关闭正文，噪声条目又开启、关闭了第二组正文。虽然专门扩展的脚本可以处理，但 Prime 1.11、1.18 和通用版都使用唯一一组正文边界，不需要增加这层逻辑。

现在改为：

```text
📚 输出协议：<|本格_正文开始|>
  世界资料、历史、规则、文风、检查与输出模板
📚 最终输出格式
防截断噪声（预设被路由或截断使用）：可选，只有噪声内容
📚 正文结束：<|本格_正文结束|>，常开
🔌 当前模型尾部
```

噪声仍处于用户要求的“最终输出格式之后”，但位于唯一的正文结束标记之前。脚本恢复单组边界检查；噪声开关不会增删边界。分区标记由脚本消费，不发送给模型。

原始噪声文件包含 13 段，编号沿用原文件的 `/60`。没有随机候选分隔符，`{{random::整段内容}}` 实际只会选中同一份内容，不能因此称为每次随机。

### 2. 加入新版方式的头部噪声

新增可选条目 `⚙️ 头部输入噪声（Prime方式）`，默认关闭，位于语言字数设置之后。语言字数设置只赋值，因此开启后噪声是首条有效系统消息，先于模型头部。

新版 Prime 的四个模型头部使用 `{{destined_prompt_noise}}`，通用版使用 `{{general_prompt_noise}}`。这些宏由配套助手注册，复制宏名本身不会生效。助手 3.15.0 已迁移旧 `缓存` 开关和 `CMD_HASH`，替换为分段噪声、固定/每次随机模式；原版默认关闭、10 段、固定模式。[原版实现](https://github.com/rhys-3/destined-journey-assistant/blob/v3.15.0/src/preset/noise.js)、[位置迁移](https://github.com/rhys-3/destined-journey-assistant/blob/v3.15.0/src/preset/noise-placement.js)

本格采用同样的功能方式，本地独立实现生成器与诊断文本，不加载原助手或它的前端界面：

- 本格专用宏：`{{bengexiuxian_prompt_noise}}`，在酒馆原生宏阶段展开。
- 10–48 段可调，支持 `fixed` 与 `random`。
- 为满足本次“头部随机数”的需求，本格脚本默认 `random`、10 段；条目本身仍默认关闭。
- 同一请求重复展开使用同一份；下一次生成才更换随机种子。固定模式保持相同种子与内容。
- 修改位置：酒馆助手 → 预设脚本 → `【本格修仙】头部噪声` → 数据中的“模式、段数、固定种子”。

头部噪声与原来的末尾固定噪声可以独立开关。新版 Prime 的输入噪声位置在头部，末尾固定文件是本格保留的另一种配置。

## 防截断：哪些变化值得参考

“请求因前缀被怎样处理”和“响应在传输或生成中被截断”是不同问题。输入噪声只改变请求文本；没有代码能凭这些文本删除供应商缓存、确认实际模型或保证回复完整。

更新页把输入噪声定位为可尝试的选项，并针对 PG 通道另给出假流式配合工具调用的建议；这是通道相关建议，不是所有模型与供应商通用的结论。[4.3.4 更新说明](https://poem-of-destiny.com/updates/v4-3-4/#noise)

| 技术 | 参考文件中的事实 | 本格处理建议 |
| --- | --- | --- |
| 头部输入噪声 | 1.18 由专用宏与助手生成，支持固定/随机 | 本次已加入本地实现；需要时单独开启并对照测试。随机前缀可能降低前缀缓存复用。 |
| 消息分区 | 1.11、1.18、通用版内嵌的消息后处理脚本完全一致 | 保留本格当前分区及 EJS 时序、空行处理，不整体覆盖。 |
| Gemini 非预填充 | 旧版已有；新版本主要补充按既有结算执行的约束 | 本格已用非预填充和用户消息结尾，不需要仅为版本号改角色。 |
| 工具一次/两次调用 | 1.11 已有；依赖助手定义函数、读取参数、还原输出，分两次时还需继续请求 | 可作为单独的通道适配项目；不能只复制尾部提示词。本次没有启用。 |
| `📤 防空回` | 1.11 与 1.18 内容相同，新版默认关闭；要求输出固定英文附录并自报 PASS | 不具备检测、续传或补全响应的代码，不建议迁入。 |
| API 思考与函数参数 | 本次对照的相关参数未变 | 没有证据需要同步修改本格的原生推理参数。 |

如果后续做工具输出，应沿用本格 `thinking → now_plot → UpdateVariable` 格式，补齐工具参数解析、普通文本兼容、流式与非流式处理，以及停止操作对两次请求的联动；确认完整后再交给 MVU 和总结消费。需要通道真实响应测试，不能以“输出变长”判定已经换回某个模型。

## 提示词与数据层：后续优先级

### 优先：上一轮已生效变量日志

命定卡新增了上一轮变更记录，让模型区分“刚发生的变化”和“当前已经更新后的状态”。本格目前已有“禁止重复扣除”等约束，但检查过的变量输出条目没有同类集中日志。

建议从实际成功应用的 MVU 更新中提取少量有用差异：时间推进、灵石消耗、物品增减、任务和状态变化。记录为“上一轮已生效”，不要求模型再执行。日志要绑定楼层与当前 swipe；重新生成、切换分支和删除楼层时随对应状态选择，主 API 与额外 API 均能读取。不要直接把原始模型命令当成已执行日志，也不要复制整个变量树。

这是比继续堆“禁止重复扣款”更有价值的改进，需要同步 MVU 核验、楼层存储和变量提示词，另行实现。

### 可选：对白自由档与情节回顾

- 参考 `⚙️ 语言与字数` / 对白配置：可把目前“40%、至少两轮”做成与“自由”并列的选项。当前条目已经有不合情境时缩减的例外，本次保留其设置，只增强公共场景规则。
- 参考 `🧩 前情回顾`：优先检索与本轮有关的承诺、线索、未完成事项，并接回当前场景。本格已有对应字段，可按实际遗漏情况补精度，不必每轮复述整份记忆。
- 参考 `⚙️ 事实结尾`：可补充不以提问催玩家接话，但不应替用户把目前“配角结尾”切换为“事实结尾”。

### 已具备：保持现有实现

- 本格使用简短公开检查结论，完整公式放在规则面板，与新版从局部思考段转向数据单的方向一致；无需恢复 7 KB 审计提示词，也无需只为名称变化重命名所有标签。
- 本格已有重要 NPC / 无主战斗单位的生成条件，不必为每个店员、守卫新增面板。
- 本格已有角色认知来源检查和独立世界推进，不必整段叠加新版同义约束。

## 不整体搬迁的部分

- 通用版把玩家定位为共同创作者，允许承接明确给出的剧情；本格是规则驱动 RPG，应保留行动尝试与结果裁决的区别。
- 命定的生命层级、命运点数、核心与复活机制、西幻化措辞属于它的世界设定；本格继续使用修仙规则。
- 原版的嵌套条件宏、前端预设助手和讨论模式是整套依赖。本格保留普通宏引擎与 EJS，实验性宏引擎无需开启。
- `now_plot`、`gametxt`、摘要、选项、MVU 输出及其消费者保持现有约定，不改为命定的 `recorder_output` 文档结构。

## 头部随机数文本的两处问题

`头部随机数.txt` 中的 `{{roll 100000 999999}}` 不是本机酒馆支持的骰子表达式，不能生成它宣称的六位随机数。`pick` 会依据聊天、文本和位置生成确定性选择，也不保证每次重新生成变化。HTML 注释仍是请求文本，没有“模型一定忽略”的保证。

因此采用本次本地噪声宏，不照抄该文件。功能名称使用“输入噪声”，不将改变前缀描述成已经清空服务端缓存。
