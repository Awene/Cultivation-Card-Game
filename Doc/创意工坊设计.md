### 5. 已知 MVP 限制与后续优化

- 当前上传采用鉴权 `multipart/form-data` 经 Worker 中转，不是预签名 R2 两阶段直传；流量增长后再升级。
- 当前没有独立缩略图，工坊详情预览使用已压缩原图。
- 当前不支持断点续传；整包只有全部文件下载并校验成功后才以事务切换为新版本。
- 当前没有独立的“修复下载”按钮；同版本本地文件缺失的专项扫描与修复尚待实现。
- 当前候选排序实际为：NSFW/SFW、调整后命中分、最长命中词、稳定散列；尚未在调整后分数相同时额外比较原始命中数。
- 当前若已选中的图片在浏览器加载阶段失败，会移除失败图片，但不会自动从第 N+1 名候选中补位。
- 当前没有玩家自定义屏蔽单张图片功能。
- 当前已有封禁状态校验，但尚无管理员封禁/解封用户的 API 和 UI。
- 当前逻辑删除图包不会立即批量物理删除其 R2 对象；尚未实现定时保留期清理任务。
- 当前没有全站暂停上传开关、Cloudflare 用量告警或压力测试结果。

## 一、需求范围

### 1. 正文自动插图

- 在“正文美化”中加入“自动插入工坊图片”总开关。
- 玩家可设置每楼最多插入多少张图片，默认 `1` 张；建议第一版允许设置为 `1～6` 张。
- 每次只分析当前楼层的正文，不读取上文文字参与关键词匹配。
- 图片统一插入当前楼层正文末尾，不穿插在段落、对白或面板中间。
- 只允许玩家已经安装且启用的图包参与匹配，不能让所有公开图包自动介入正文。
- 匹配和排序全部在玩家浏览器本地完成，正文内容不得发送给创意工坊服务器。

### 2. 图包共享

- 每个 Discord 用户可以创建多个图包。
- 图包拥有独立名称、简介、类别、版本、状态和图片列表。
- 图包类别固定为：`风景`、`人物`、`其他`。
- 玩家可以上传、修改、发布、下架和删除自己的图包。
- 其他玩家可以浏览、安装、启用、停用、更新或卸载图包。
- 图包下架后立即退出公开目录及远程匹配清单，但无法强制删除其他玩家此前已经缓存到本机的副本。

### 3. 每张图片的信息

每张图片至少包含：

| 字段 | 要求 |
| --- | --- |
| 图片 ID | 服务端生成，永久稳定，不使用文件名作为 ID |
| 所属图包 | 必填 |
| 角色名 | 人物图包必填；风景、其他图包留空 |
| 图片类别 | `sfw` 或 `nsfw` |
| 关键词 | 必填，支持多个；用于正文匹配 |
| 原图对象键 | 服务端保存，不直接暴露 R2 管理凭证 |
| 缩略图对象键 | 后续流量优化使用；MVP 暂用已压缩原图预览 |
| 宽、高、格式、大小 | 服务端记录并复验 |
| 内容哈希 | 用于完整性校验和重复文件识别 |
| 状态 | `active / hidden / removed` |
| 创建及更新时间 | 服务端生成 |

人物图包中的“角色名”默认同时作为一个隐式关键词参与匹配。例如角色名为“白蕊弦”，即使作者没有在关键词列表中重复填写“白蕊弦”，正文出现该名称时仍可命中。

## 五、图包生命周期

```text
草稿 draft
  ↓ 作者发布；服务端自动校验通过后立即公开
已发布 published
  ↓ 作者修改；校验通过后立即更新并增加版本号
已发布新版本 published
  ↓ 作者下架
已下架 hidden
  ↓ 重新发布或永久删除
published / removed
```

规则：

- 新图包默认是草稿，不进入公开目录。
- 发布前执行服务端字段、文件和配额校验。
- 不设置发布前人工审核；任意已登录的 Discord 用户均可发布图包，自动校验通过后立即公开。
- 已发布图包修改角色名、关键词、图片类别或图片内容后立即生成新版本并公开，不进入审核队列。
- 封禁用户的数据状态已经预留，但管理 API/UI 尚待实现。
- 图片对象采用不可变对象键。MVP 可修改图片资料；若要替换图片内容，当前操作是删除旧图后上传新图。
- 下架立即从目录和最新清单移除；R2 文件进入保留期，建议 `7～30` 天后物理删除，以支持误操作恢复。
- 永久删除后仍不能远程清除玩家设备中已经下载或缓存的副本，界面和用户协议中需要明确说明。

## 六、图片上传与处理

### 1. 支持格式

第一版建议仅允许：

- JPEG
- PNG
- WebP

明确不支持 GIF。也不允许 SVG，避免脚本、外链和 XML 解析带来的 XSS 风险。客户端和服务端均只接受 JPEG、PNG、WebP。

### 2. 尺寸规则

- 原图宽、高均不得超过 `1600px`。
- 若任意一边超过 1600，则按比例缩放：

```text
scale = min(1600 / width, 1600 / height, 1)
newWidth  = round(width  × scale)
newHeight = round(height × scale)
```

- 例如 `2400 × 1200` 会缩放为 `1600 × 800`。
- 不拉伸、不裁切、不改变宽高比。
- 前端在上传前通过 Canvas 完成正常用户的压缩，减少网络流量并通过重新编码清除 EXIF。
- 服务端不能信任前端结果，仍需检查真实文件类型、文件头、尺寸和大小；不合规文件直接拒绝。

### 3. 输出策略

推荐：

- 普通照片或 AI 插图转为 WebP，质量建议 `0.88～0.92`。
- 需要透明通道的 PNG 可转为无损 WebP，或在第一版保留 PNG。
- 同时生成约 `320～480px` 长边的缩略图，用于工坊列表。
- 原始本地文件名不作为远程路径，R2 对象键由随机 UUID 和内容哈希组成。

### 4. 上传协议

目标架构不照搬示例工坊将整张 Data URL 塞进 JSON 的做法。MVP 先使用带鉴权的 `multipart/form-data` 上传到 Worker，由 Worker 限流、复验后写入私有 R2；单文件上限 6MB。用户量或上传流量增长后升级为两阶段直传：

```text
1. 前端登录并提交图片元信息
2. Worker 签发短期、单对象上传凭证
3. 浏览器直接 PUT 原图和缩略图到 R2
4. 前端向 Worker 提交 finalize 请求
5. Worker复验对象后写入 D1；草稿图包内图片置为 active，已发布图包的新图片校验通过后立即公开
```

这样可以避免 base64 体积膨胀，也不会把 R2 密钥交给玩家。

MVP 配额为：每个账号最多 20 个未删除图包、每包最多 200 张未删除图片、每账号最多 1GB 有效图片；此外另有 OAuth、建包和上传接口频率限制。配额值可在运营数据稳定后调整。

## 七、正文提取范围

“只判断本楼正文”应严格定义为：

- 只读取当前消息 iframe 正在渲染的原始 AI 正文。
- 不读取更早楼层的正文参与关键词计数。
- 不读取玩家输入、角色卡、世界书、思维链或提示词。
- 在匹配前排除以下内容：
  - `<UpdateVariable>` 及变量补丁。
  - 思维链和被配置为隐藏的标签。
  - 角色信息、战斗、物品等结构化面板原文。
  - HTML 标签、已有图片的 `alt/src`、脚本和样式。
  - 工坊先前插入的图片标记。

用于匹配的纯文本只存在于当前 iframe 内存中，处理完即可释放，不写日志、不上传。

## 八、关键词规范化与命中

### 1. 关键词规则

- 作者通过标签输入多个关键词；服务端保存为字符串数组。
- 去掉首尾空白并执行 Unicode NFKC 规范化。
- 拉丁字母匹配时忽略大小写；中文按字面匹配。
- 关键词按普通字符串匹配，不允许作者提交任意正则表达式。
- 去重后保存；建议每张图片至少 1 个、最多 30 个关键词。
- 建议单个关键词为 2～30 个字符；确有意义的单字地名可由管理员例外放行。
- 人物图的角色名自动加入隐式关键词。

### 2. 命中频率

对每张候选图计算：

```text
rawHitCount = Σ 当前楼正文中每个关键词的非重叠出现次数
```

只有 `rawHitCount > 0` 的图片进入候选池。

示例：某图关键词为 `[白蕊弦, 双修, 秘籍]`，正文中“白蕊弦”出现 2 次、“秘籍”出现 1 次，则原始命中频率为 `3`。

## 九、选图优先级

### 1. 候选过滤

候选图片必须同时满足：

- 所属图包已被当前玩家安装并启用。
- 图包和图片状态为已发布。
- 图片至少命中一个关键词。
- SFW 与 NSFW 图片始终允许参与匹配，不提供隐藏 NSFW 的客户端开关。

### 2. 历史频率惩罚

虽然不读取上文文字，但可以读取本聊天中此前成功插入过的“图片 ID 记录”。惩罚只应用一次，不随历史出现次数累计：

```text
historyCount  = 本聊天较早楼层中该图片成功插入的次数
historyFactor = historyCount > 0 ? 0.7 : 1.0
adjustedHits  = rawHitCount × historyFactor
```

即图片只要曾在上文成功显示过，当前命中分数就统一降低 30%；无论此前出现过一次还是多次，都不会继续累计降低。示例：

| 历史出现次数 | 系数 |
| ---: | ---: |
| 0 | 1.000 |
| 1 | 0.700 |
| 2 | 0.700 |
| 3 或更多 | 0.700 |

只有成功显示的图片才写入历史；网络加载失败的图片不计入历史。

### 3. 排序规则

当前 MVP 按以下优先级逐层比较：

1. `nsfw` 优先于 `sfw`。
2. `adjustedHits` 从高到低。
3. 关键词最大长度从高到低，降低短词误命中的优势。
4. 若仍相同，使用 `聊天 ID + 消息 ID + 图片 ID` 生成的稳定散列打破平局。

设计上仍建议后续在第 2、3 项之间补充 `rawHitCount` 从高到低的比较，用于区分“原始命中较高但受历史惩罚”与“首次出现但调整后分数相同”的图片。

采用稳定散列而不是普通随机数，保证同一楼层重复渲染时不会无故换图。

### 4. 多图选取

- 按上述排序依次取前 N 张，N 为玩家设置的单楼上限，默认 1。
- 同一张图片在一楼中最多出现一次。
- 当前图片加载失败时会移除失败卡片；按候选顺序自动补位属于后续优化。
- 多张图片统一在正文末尾按响应式网格展示；手机端单列，宽屏可双列。

## 十、楼层稳定性与历史记录

当前父页面 IndexedDB 数据库名为 `cultivation-illustration-workshop`，版本为 `2`，实际对象仓库为：

- `packs`：已安装图包、manifest、版本、启停状态和本地占用。
- `images`：完整图片 Blob、哈希和所属图包。
- `settings`：API 地址、总开关、单楼上限、更新周期和最近检查时间。
- `auth`：Discord 登录后的短期服务端会话。
- `selections`：每个聊天、楼层和正文哈希对应的稳定选图结果。
- `history`：图片在当前聊天中成功显示的累计记录。
- `displays`：聊天、楼层和图片的成功显示去重标记，防止 iframe 重渲染重复计数。

楼层选图记录键建议为：

```text
chat_id + message_id + body_content_hash
```

- 相同消息和相同正文再次渲染时直接复用原选图。
- 重新生成导致正文哈希变化时重新匹配，并替换该楼记录。
- 删除、回退消息后的历史惰性清理尚未实现；当前记录留在本地数据库中。
- 历史记录只存图片 ID，不保存命中的正文或关键词上下文。

## 十一、图包下载、本地安装与自动更新

### 1. 玩家主动下载

创意工坊采用明确的“浏览后手动下载”模型，不采用正文命中时临时从云端取图：

```text
打开创意工坊 → 浏览/搜索图包 → 查看详情和预计占用空间
              → 玩家点击“下载图包”
              → 下载 manifest 和全部完整图片
              → 校验版本、文件哈希和完整性
              → 写入 IndexedDB 并标记为“已安装”
              → 默认启用，可在图包管理页关闭
```

- 未经玩家点击下载的图包不会保存在本地、不会参与正文匹配，也不会因正文出现关键词而自动联网取图。
- 当前下载前显示图包资料、版本和图片数量；SFW/NSFW 汇总及精确预计占用仍可继续补充。
- 下载过程中显示完成数/总数；当前不支持跨会话断点续传。
- 只有 manifest 与全部必需图片均校验成功后才切换为“已安装”，避免半个图包参与匹配。
- 浏览详情当前直接使用服务端已压缩原图，属于普通浏览器网络缓存，不代表图包已安装。
- 浏览器若因空间压力清除了 IndexedDB 文件，当前可能表现为图片缺失；专项完整性扫描和“修复下载”按钮属于后续任务。

### 2. 已安装图包管理

创意工坊提供独立的“已安装图包”管理页面，每个图包显示封面、名称、作者、版本、图片数量、本地占用、更新时间和当前状态，并提供：

- 启用/停用开关：只有已安装且启用的图包参与正文匹配。
- 查看详情：查看图片、关键词、作者和版本记录。
- 立即检查更新。
- 修复下载：计划功能，当前尚无独立按钮。
- 卸载：删除本地图包 manifest 与图片文件，使其退出匹配；不影响作者云端图包。

下载完成后图包默认启用。停用只改变匹配状态，不删除本地文件；重新启用时不必再次下载。正文美化设置区只提供总开关和已启用图包概览，完整管理操作统一进入创意工坊的“已安装图包”页面。

### 3. 已安装图包自动更新

图包一经安装，更新采用自动模式，不要求玩家逐次确认：

1. 客户端在打开创意工坊以及每次酒馆会话首次加载时检查已安装图包版本；同一客户端设置更新检查冷却时间，避免重复请求。
2. 服务端返回轻量版本清单；版本未变化时不下载图片。
3. 版本变化时下载新 manifest，对比图片 ID、内容哈希和对象版本，只下载新增或发生变化的文件。
4. 所有新文件校验成功后，以事务方式切换到新版本，再删除已经移除的旧文件。
5. 更新失败时继续使用最后一个完整版本，并在管理页显示失败原因和“重试”按钮。
6. 自动更新不会改变玩家的启用/停用选择；原本停用的图包更新后仍保持停用。
7. 作者下架图包后，客户端在同步时将其标记为“已下架并停用”，不再用于新楼层；本地文件由玩家卸载，或在管理页确认后清理。

服务端使用版本号、内容哈希及 `ETag / If-None-Match` 支持增量更新。已安装图包的图片全部从本地读取，正文渲染本身不为取图访问云端。

## 十三、Discord 登录

参考示例工坊的交互形式，但不照搬其前端信任 `owner_discord_id` 的方式。

任何 Discord 用户都可以登录、上传和发布图包，不要求加入指定 Discord 服务器。OAuth 仅申请识别用户所必需的最小权限，不申请读取服务器、好友或聊天内容。

推荐使用 Discord OAuth2 Authorization Code + PKCE：

```text
1. 工坊 iframe 请求登录
2. 打开 Discord OAuth 弹窗
3. Discord 回调到 Worker
4. Worker用 code 换取身份并创建服务端会话
5. 回调页用一次性 code 通知工坊 iframe
6. 工坊 iframe 建立短期访问会话
```

安全要求：

- Discord Client Secret 只存在 Cloudflare Secret 中。
- 浏览器不能提交一个 Discord ID 就被视为该用户。
- OAuth `state` 必须校验；推荐同时使用 PKCE。
- `postMessage` 必须指定精确的目标 origin，不允许 `*`。
- 登录弹窗返回的一次性 code 使用后立即失效。
- 写接口必须验证服务端会话；读公开图包接口可以匿名访问。
- 管理员权限由数据库中的 Discord ID 白名单控制，不能由客户端字段决定。

由于工坊运行在酒馆 iframe 中，需要特别测试第三方 Cookie 限制。若 Cookie 在部分浏览器中不可用，可采用短期访问令牌保存在 iframe 内存或 `sessionStorage`，不把长期刷新令牌暴露给正文 iframe。

## 十五、信息安全与隐私

### 1. 正文隐私

- 正文、聊天历史、MVU 变量、世界书内容不发送到创意工坊。
- API 只接收图包操作、图片 ID、版本及必要的登录信息。
- 匹配日志默认不上传；调试日志也不得打印正文。

### 2. 上传安全

- 只接受 JPEG、PNG、WebP；检查魔数，不只相信扩展名和 MIME。
- 服务端限制文件大小、尺寸、上传次数和单用户总容量。
- 重新编码以删除 EXIF、GPS、相机和缩略图隐私信息。
- 拒绝 GIF、SVG、HTML、脚本、可疑多态文件和损坏图片。
- 上传地址短期有效、绑定唯一对象键和内容类型。
- 未 finalize、校验失败或被永久删除的孤立对象定期清理。
- 对重复哈希给出提示，避免反复占用空间。

### 3. Web 安全

- 所有名称、简介、关键词和作者文本在输出 HTML 前转义。
- 工坊页面设置严格 CSP，限制脚本、连接和图片来源。
- R2 管理密钥、Discord Secret、会话签名密钥不得进入角色卡或前端仓库。
- API 实施 CSRF、重放、越权和对象所有权检查。
- 作者只能修改、下架自己的图包；管理员操作写入审计日志。
- 限制登录、上传和搜索频率，防止刷接口和费用攻击。

### 4. 内容安全

- SFW 与 NSFW 必须由作者逐图标记。
- 不设置发布前人工审核，图包校验通过后立即公开。
- 客户端不提供举报入口；若未来公开运营，需要另行确定版权下架与违规内容的外部联系渠道。
- 未登录用户不能上传。
- 涉及公开玩家上传时，需要展示简短的上传协议，说明授权范围、下架行为及本地缓存无法远程撤回。

需要配置的生产值至少包括：

| 名称 | 是否保密 | 来源/用途 |
| --- | --- | --- |
| `DISCORD_CLIENT_ID` | 否 | Discord Application ID |
