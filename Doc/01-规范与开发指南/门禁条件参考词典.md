# 门禁条件参考词典

供作者和 AI 编写条件配置时按需读取，不作为常驻剧情指令，不注册为世界书条目。大小事件的叙事组织见[事件骨架与节点编写参考](事件骨架与节点编写参考.md)。

## 条件的职责边界

下方 `chapters` 配置示例用于长线。小事件沿用当前集合的条件、唯一名称、待回应和完成记录，不因共用节点写法新增幕次配置；同地区／宗门小事维护在集合内，遵守统一入口让位与集合内单轮唯一选择。

条件配置只维护注册入口、显式顺序、地区筛选、专属资格、合法幕次及不可绕过的硬条件。地区不拥有独立放行权；不要加入行动关键词、回应识别、发奖或自动推进。

| 条件类别 | 用途 | 编写注意 |
|---|---|---|
| 地区筛选 | 缩小尚未开启剧情的候选范围 | 已开启线不能仅因离开所属地区而被排除；跨地区传音由本线说明 |
| 修为、身份 | 明确不可绕过的资格 | 区分实际修为与进度，保留原定门槛；身份字段不证明正文已完成入门考核 |
| 专属开局授权 | 限定只能由某开局开启的剧情 | 检查已保存的对应资格，不能凭同名道具或提及名称解锁 |
| 前置结果、实际分支 | 限定后续路线 | 读取已经发生的结果，不能以问询、意向或相似关键词推定完成 |
| 物品、数量与技艺 | 路线确有要求时核对资格 | 先核对当前字段与配置接口；持有不等于已使用、已交付或已消耗 |
| 合法幕次 | 确定当前可加载的幕 | 使用本线配置中的精确标识，不为观察、探索、询问或等待回应另造阶段 |

表中的类别不是必须新增的函数或字段；从当前实现选取所需条件，不复制整套词典。叙事进入条件、完成／退出标志与下一幕线索放在剧情世界书“幕次说明”；AI 根据正文判断，不复制回条件配置。地点、玩家是否愿意、是否已经行动等叙事时机也在世界书说明，不能由关键词替玩家决定。明确的不可绕过的地点资格按本线既定契约核对。

## 条件配置示例

以下展示配置形状，放在对应地区配置中，名称须与实际注册一致。`rank` 为示意辅助函数，必须从当前实现核对或提供，不能把此片段当作可独立运行的代码。

```ts
{
  name: '示例剧情', entry: '[事件]示例剧情', order: 100,
  region: ({data}) => data.地点?.地域 === '示例地区',
  chapters: [
    { name: '第一幕', condition: '筑基及以上', gate: ctx => rank(ctx) >= 2 },
    { name: '第二幕', condition: '金丹及以上', gate: ctx => rank(ctx) >= 3 },
  ],
}
```

专属开局使用 `authorized` 检查已保存的对应开局资格；具体存储位置及函数签名以当前实现为准，不自行造一套判断。

## 接入与核对

新增配置后加入 registry，登记世界书入口，运行现有 sync_plot_focus 流程生成公共入口、合法幕次表及逐幕条件表。未知幕次与重复注册应离线报错。检查硬条件成立但正文尚未开启、条件不足、暂离返回、分支不同及无剧情模式等情况，避免把资格成立当成实际推进。

仅按当次授权同步完整测试卡，真实测试由用户发送输入。本文迁移不改变其他地区既有门禁实现，也不使示例自动生效。
