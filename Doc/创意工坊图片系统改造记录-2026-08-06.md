# 创意工坊图片系统改造记录（2026-08-06）

## 改造范围

本次改造同时涉及三个仓库：

- `Cultivation-Card-Game`：创意工坊 Cloudflare Worker、D1 数据结构和接口校验。
- `tavern_helper_template-main`：创意工坊前端、本地缓存、安装图包选图服务和正文图片播放器。
- `cultivation-rule-router`：向同源脚本提供逐楼层世界书条目路由状态查询。

目标是解决图片重复请求、并发加载失败、上传时强制重载、已上传图片难以管理等问题，同时移除失败的图片关键词体系，改为以“角色名/别名 + SFW/NSFW”为核心的数据和选图模型。

## 一、图片浏览与本地缓存

### 浏览列表

- 工坊图片不再在进入页面时全部并发下载。
- 图片卡片进入可视区域后才请求图片，减少瞬时网络压力。
- 公共图片和本人未发布图包图片分别使用正确的鉴权请求。
- 下载成功的预览图写入独立 IndexedDB 缓存，再次进入图包时直接读取本地 Blob。
- 同一个图片 ID 的并发请求会合并为同一个 Promise，避免重复下载。
- 加载失败不会让图片永久失效，卡片提供重试入口。
- 加载状态改用高对比度遮罩、旋转图标和清晰文字，避免文字与背景颜色接近。

### 已安装图包

- 完整图包仍以 IndexedDB Blob 方式离线保存。
- 正文显示只为当前图片创建 Object URL，不会同时触发所有图片的浏览器解码。
- 页面卸载或图包库变化时释放 Object URL 和轮播计时器。

## 二、上传与管理流程

### 上传

- 上传多张图片时，共用本次填写的图片分级、角色名和角色别名。
- 人物图包必须填写角色名；角色别名为可选项，多个别名使用中文或英文逗号分隔。
- 风景和其他类图包不要求角色名或别名。
- 图片仍会在客户端移除元数据、限制最大边并压缩后上传。
- 单张上传成功后直接把返回的图片加入当前管理列表，并复用刚处理好的本地 Blob 作为预览，不再重新加载整个图包的全部图片。
- 多图上传允许部分成功；失败图片会被跳过并汇总原因，不会阻止其余图片继续上传。

### 已上传图片管理

- 每张图片可单独修改：
  - SFW/NSFW 分级；
  - 角色名；
  - 角色别名。
- 支持选择一张、多张或全选后批量删除。
- 未选择显示“＋”，已选择显示“✓”，不再依赖容易因控件尺寸而看不出的开关外观。
- 删除后同步更新预览图、本地缓存和图包摘要。
- 关键词查看器、关键词批量修改和关键词数量展示已经全部移除。

## 三、关键词系统移除

### 对外数据模型

图片公开结构由：

```text
character_name + rating + keywords
```

改为：

```text
character_name + aliases + rating
```

- 客户端不再上传、读取或展示图片关键词。
- 服务端发布图包时不再要求每张图片至少有一个关键词。
- 新上传图片会把遗留的 `keywords_json` 写为空数组，但运行时不读取它。
- 按约定，旧数据库列 `keywords_json` 暂时保留，避免破坏已有 D1 数据；它是完全休眠的兼容字段。
- 离线图包的新导出内容只包含别名和分级，不再导出关键词。旧离线包中的额外关键词字段会被忽略。

### 数据库迁移

新增迁移：

```sql
ALTER TABLE images ADD COLUMN aliases_json TEXT NOT NULL DEFAULT '[]';
```

迁移文件为 `workshop/migrations/0006_image_aliases.sql`。现有图片升级后别名默认为空数组。

## 四、正文选图规则

### 角色选择

1. 只遍历已安装、已启用且可用的“人物”图包。
2. 按规范化后的 `character_name` 聚合同一角色在不同图包中的图片。
3. 将该角色所有图片的别名合并去重，角色名和别名都参与本楼正文匹配。
4. 统计每个角色名及其别名在本楼正文中的出现次数总和。
5. 选择出现次数最高的角色。
6. 若次数相同，选择在正文中最后一次出现位置更靠后的角色。

角色名和别名匹配会进行 NFKC 规范化，并对拉丁字符忽略大小写。

### 没有角色时

- 没有任何角色名或别名命中时，先尝试已启用的风景图包。
- 没有风景图片时再尝试其他类图包。
- 两类都没有可用图片时，本楼不插入图片。

旧的关键词评分、历史衰减和“每楼最多插图”逻辑不再参与选图。正文每楼只创建一个图片播放器。

## 五、SFW/NSFW 初始判断

人物命中后，工坊通过规则路由插件查询本 AI 楼层中以下条目的状态：

```text
[mvu_plot][NSFW]基础指导
```

- 条目在本楼路由的 `kept` 或 `linked` 中：初始选择 NSFW。
- 条目在本楼路由的 `hidden` 中：初始选择 SFW。
- 楼层没有路由记录、插件未运行、路由失败或记录中没有该条目：检测失败，初始按 SFW 处理，并在酒馆顶部显示警告。
- 如果所有相关图包都没有目标分级，则退回显示另一分级的现有图片。因此只有 NSFW 图片时可以正常显示 NSFW。

风景和其他类图片不执行 NSFW 世界书判断，默认优先 SFW，没有 SFW 时显示现有 NSFW。

## 六、正文单图播放器

播放器提供以下控制：

- 上一张；
- 下一张；
- SFW/NSFW 分级切换；
- 图包切换；
- 10 秒自动轮播开关，默认关闭；
- 全屏查看。

约束如下：

- 左右切换只在“当前图包 + 当前分级”内循环。
- 自动轮播只在“当前图包 + 当前分级”内循环。
- 切换图包只在含有当前分级图片的图包之间循环。
- 以上三个操作都不会暗中跨越 SFW/NSFW；只有玩家点击分级按钮时才会切换分级。
- 点击分级按钮时，优先留在当前图包；当前图包没有目标分级时，寻找拥有该分级的其他图包。
- 同一角色存在多个已安装图包时，玩家选择的图包写入创意工坊全局设置，以角色规范名或图片类别作为记忆键；后续楼层会优先使用该图包。
- 桌面端控制按钮默认隐藏，鼠标悬停或键盘聚焦播放器时出现。
- 无悬停能力的触屏设备和窄屏设备始终显示紧凑控制栏。

## 七、规则路由插件接口

规则路由插件升级至 `v0.19.2`，新增：

```js
CultivationRuleRouter.getFloorEntryState(messageId, entryName)
```

返回结构：

```ts
{ ok: boolean; enabled: boolean; reason?: string }
```

- `enabled: true` 表示该条目在本楼被命中或关联开启。
- `enabled: false` 且 `ok: true` 表示该条目在本楼被路由隐藏。
- `ok: false` 表示无法可靠判断，调用方必须使用安全默认值。

接口只读取 AI 楼层已经保存的 `extra.crr_route`，不会重新执行路由，也不会修改世界书开关。

## 十、上线顺序

为了避免新 Worker 先访问尚不存在的 `aliases_json` 列，线上发布必须按以下顺序：

1. 在 `Cultivation-Card-Game/workshop` 执行远程 D1 迁移。
2. 部署创意工坊 Worker `v0.3.0`。
3. 发布或更新 `cultivation-rule-router v0.19.2`。
4. 发布 Tavern Helper 创意工坊构建产物和正文美化文件。
5. 刷新 SillyTavern，确认创意工坊桥版本为 `0.3.0`，并用新 AI 楼层验证路由状态读取。

旧楼层没有 `crr_route` 记录时出现一次安全降级提示属于预期行为。
