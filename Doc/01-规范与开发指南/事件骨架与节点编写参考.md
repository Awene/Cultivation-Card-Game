# 事件骨架与节点编写参考

供作者与 AI 设计小事件与长线剧情时按需读取。本文不注册为世界书、不进入角色卡导出，也不整篇加入运行提示；实际世界书只保留当前小事件或长线当前幕所需的情境、交互边界、完成标志和状态事实。

本文说明四类节点的设计方法、组合方式、情境原型、停笔指导和奖励安排，并分别提供轻量小事件与按幕长线的完整样例。

运行职责见[事件写作规范](事件写作规范.md)；已落地的南疆规则见[逐幕条件表](../03-专项重构与验证/南疆逐幕条件表.md)与[按幕改造验证](../03-专项重构与验证/剧情按幕改造-实施与验证.md)。其他地区保留既有行为，不能因本文更新而自动迁移。

## 1. 共用的四类节点

事件由开始、中间、分支、结束四类节点灵活组合。小事件可采用“开始 → 结束”，需要时复用中间与分支；长线不限三幕、不限一处分支。规模和复杂程度不构成新增节点类型的理由。

| 节点 | 叙事职责 | 可以重复使用的情境 |
|---|---|---|
| 开始节点 | 建立引子、悬念与第一次交互 | 专属开局、求救、遗迹显露、异宝共鸣、宗门警变 |
| 中间节点（推进／发展） | 让信息、关系、空间或冲突逐步变化 | 调查交涉、潜行脱险、机关探索、阶段战斗 |
| 分支节点（抉择） | 呈现有后果的道路，等待玩家决定 | 去留攻守、多向探索、异宝处置、危局应变 |
| 结束节点（收束／结算） | 兑现实际结果、交代余波并结束本线 | 成功、失败、拒绝后的终止、不同路线的独立结局 |

**节点描述叙事用途；幕用于长线的加载与进度保存；规模描述事件范围。** 三者分别判断。小事件可以多轮交互、有分支，不因此必须建幕次或长线历练。四类节点也不机械对应四个持久化状态。

四类节点的共用方法如下。带“幕名、下一幕、历练”的填写项和面板要求仅适用于长线；小事件使用第 6 节的集合记录与收束方式。

## 2. 开始节点：建立牵引，交出第一次行动权

### 原型与条件素材

| 原型 | 引子举例 | 设计时需核对 |
|---|---|---|
| 专属开局 | 残简传承、吞果苏醒、特定身世 | 对应开局授权；已初始化内容不重复发放或播放 |
| 生灵突发 | 负伤者求救、来客夜叩、敌手堵截 | 人物为何在场、玩家为何能感知、是否可拒绝 |
| 秘境踏足 | 绝地异变、禁制裂隙、古殿显露 | 实际接近地点与必要资格；不代替玩家入内 |
| 异宝共鸣 | 古卷发热、信物鸣动、神识传音 | 信物来源、共鸣条件、信息知情边界 |
| 天地浩劫／宗门警变 | 异象、警钟、护山阵震动 | 波及范围、宗门身份或前置因果 |

条件按需选择，不复制整套条件词典。硬资格与注册放在当前条件配置中；世界书描述叙事时机及实际交互。专属开局不能凭同名物品、地点或提及剧情名称解锁，也不为已由开局确定的事实堆叠无意义的重复判断。

### 三层开场写法

1. **场景与感官底色**：选择对当前冲突有用的光影、温度、声音、灵压或周围动静，建立空间与气氛。
2. **情境引力切入**：让负伤来客、遗迹显露、异宝异动或警变破坏原有秩序，呈现值得回应的问题。
3. **交互核心呈现**：将笔触收束到具体对象，例如来客的发问、古门的阵盘、掌心躁动的古卷。

三层是写作方法，不要求每次固定三段。让悬念可以被玩家接触，不在首轮倒尽真相或替玩家走完考验。

### 停笔锚点

- NPC 型：话音落下、对方等待答复，保留接纳、怀疑、拒绝或另行处理的余地。
- 秘境型：门户或裂隙显露，停在需要决定是否靠近、进入或调查之处。
- 异宝型：异动可被感知，停在是否探查、注入灵力或放下物件之前。
- 警变型：危险与可行动方向已经清楚，停在玩家选择如何应对之前。

不能把“出现引子”写成玩家已接受、触碰、进入、开口或投入战斗。开局中用户已经确认的事实可以承接，不因此补写尚未决定的后续行动。

### 长线开始节点填写表（小事件见第 6 节）

```text
幕名：
进入条件：硬资格；适合开启的实际场景。
已成立事实：哪些由开局或先前正文确认。
情境：场景底色 → 异变引子 → 眼前交互核心。
玩家边界：哪些反应必须等玩家决定。
停笔点：
本幕完成／退出标志：不能仅写“已输出面板”。
下一幕条件与线索：
状态事实：本幕实际开启后保存同名历练及当前幕，不预写选择、胜利或奖励。
```

## 3. 中间节点：承接行动，让一段事件充分展开

以下四种中间节点均可反复取用，不限人物对话，也适用于无 NPC 场景。

| 原型 | 可描写的变化 | 合适的交互与停笔位置 |
|---|---|---|
| 线索交涉与秘辛推演 | 言语试探、证据比对、隐秘动机、逐步揭露信息 | 一条可验证的新线索、对方反问或新的疑点；让玩家决定追问与判断 |
| 险境周旋与潜行遁逃 | 追兵、风雨、恶劣地貌、资源消耗、可利用的地利 | 新的藏身处、岔路、追兵动向；不预定玩家逃脱或牺牲 |
| 机关破解与空间深入 | 铭文、阵纹、机括、空间变化与试探反馈 | 机关反馈或新入口显露；不替玩家继续触发、进入或拿取 |
| 阶段激斗与险象博弈 | 招式后果、地形利用、负伤与战局变化 | 当前行动结果和下一处威胁／机会；不预定胜利、击杀或投降 |

### 推进与节奏

- 依据玩家已表达的行动写结果，不从写作示例中自动取用玩家动作。
- 一轮可以产生实质进展，但不跨过尚待玩家决定的关口。长线不在结束本幕后同轮开启下一幕。
- 小事件和长线都可多轮探索；对话结束、调查有结果或危机解除等事实满足约定的退出标志后才收束。长线在此结束本幕，小事件按集合记录收束。
- 紧凑叙事不能解释成每轮强制改阶段；多轮探索对应同幕自然交互，不创建探索、待询问、待回应等细碎长线状态。
- 不重复播放开场；长线同幕不重复输出面板，小事件始终不输出剧情面板。真实进展仍通过普通变量流程保存。

### 合理阻力的适用边界

禁制、险恶地形、人物戒备和实力差距可以形成合理阻力，前提是有既定世界事实支持，并允许玩家应对。不能为守住预定路线临时捏造阻碍、否定合理解法、替玩家失败或拒绝玩家离场。玩家提出新办法时，按现有条件判断结果；确实改变作者已确认范围时再讨论。

```text
长线中间节点填写参考（小事件不填写幕字段）：
中间节点用途：交涉／脱险／机关／战斗，或其组合。
承接事实：上轮发生了什么，玩家本轮实际做了什么。
当前变化：新增信息、人物反应、环境反馈与实际代价。
仍待决定：留下哪一个有意义的行动口。
本幕退出检查：哪些事实已满足，哪些仍未发生。
记录：只更新实际进展；未结束就保持当前幕，不因问询另建状态。
```

## 4. 分支节点：呈现选择，保留不同后果

分支负责产生真正的路线差异，不只是把两句不同台词接回同一结果。支持双路、多岔路与条件解锁方式；不限二选一，也不强制生成专属选项按钮。

| 原型 | 可选道路示例 | 需要提前写明的后果 |
|---|---|---|
| 生灵对峙 | 潜行脱困、正面迎敌、协商或拒绝托付 | 同行者命运、关系、风险、获得何种线索 |
| 秘境岔路（可无 NPC） | 神兵冢、藏药阁、迷阵暗道 | 各路内容、可否回返、汇流点、独立结局 |
| 异宝处置（可无 NPC） | 炼化、封印、摧毁或暂不处置 | 代价、所得、遗留隐患及后续进入条件 |
| 危局应变 | 守阵、疏散、突袭或另寻办法 | 不同对象的损失与存续、后续局势 |

条件解锁路线可以使用已确认的修为、物品、技艺或前置结果。作者需写清条件和可被发现的线索；没有资格不能凭玩家提及分支名越过硬限制，也不能泄露角色尚不知道的隐藏结局。

### 停笔与判定

把危机、道路及玩家能够感知的代价讲清楚，在决定发生前停笔。不能让 NPC 替玩家接受托付，也不能描写玩家已经推门、炼化、交出物品或选定阵营。

- 玩家问价、追问、犹豫、讨价还价：继续当前交互，尚未产生分支结果；小事件保留待回应，长线保持当前幕。
- 玩家明确选择：记录实际选择；若该路线要求行动落实，再根据正文记录实施结果，不能把意向当成功。
- 玩家采取第三种办法：依据既定条件处理，不强行归入最相似的关键词路线。
- 甲乙路线可接不同中间节点，再汇流或分别结束；后续内容应消费已记录的真实分支。
- 小事件分支不建幕次、不出剧情卡。长线本幕内抉择不改幕次、不再弹卡；若分支本身属于新幕，仅在该幕实际开启时按统一规则出卡。

```text
分支关口：玩家面对什么问题。
可感知信息：已知道路、危险和代价；隐藏信息的揭示条件。
甲路线：选择依据 → 实际实施／成功条件 → 后果 → 下游节点。
乙路线：选择依据 → 实际实施／成功条件 → 后果 → 下游节点。
其他行动／暂缓／拒绝：如何继续或退出，是否真的终止全线。
停笔点：在实际决定前停笔。
记录：只写已发生的选择和结果，不预发另一分支奖励。
```

## 5. 结束节点：兑现结果，收束事件

结束节点可以承接任何一条路线。成功、失败、拒绝与牺牲可以有不同结局；小事件按自身收束条件结束，长线还须区分本幕结束与全线终止。

### 收束的三个层次

1. **场景余波**：危险消退后的声音、光影、遗迹变化、人物反应，与开场形成呼应。
2. **实际所得与代价**：哪些物品到手、关系改变、损失发生；区分获赠秘籍与真正学会、得到丹药与服用生效。
3. **后续余地**：可以呈现离场机会或新的目标，但不替玩家远行、长期闭关、修成神通或作人生决定。

### 六类奖励参考

以下供作者挑选，非每线必发六类，品质和数值按具体剧情核定。名称、数量、品质、条件、效果、来源与领取时点须按当前物品功法、经济规则和既有设定核定。

| 类别 | 可选素材与示例 | 兑现边界 |
|---|---|---|
| 功法与神通 | 心法、攻击、身法、护体、神识、阵法；例如《青木长生诀》秘籍 | 实物入库、获得传授、参悟与掌握分别判断；不默认直接学会 |
| 修为／寿元／道基 | 修行心得、延寿灵果、根骨或悟性变化、灵根纯化 | 先有实际修炼、服用或蜕变；不因结局自动突破 |
| 装备与神兵 | 玄铁煞刃、青木软甲、两仪护心佩等设计素材 | 攻防、位置、使用条件与标签按当前结构校验；获得不等于装备 |
| 资材／丹药／货币 | 太素清心丹、紫霄九雷符、千年雷击木、配方、灵石 | 写明数量与来源，核对实际取得和消耗；符箓、素材属性遵循当前规则 |
| 状态效果／道韵 | 枯荣真意、心境顿悟、阵法加护 | 说明触发、效果、持续或退出条件；永久效果必须有设计依据 |
| 灵兽／身份／羁绊 | 踏雪青灵狐契约、宗门晋升、人物结缘 | 收服、契约、正式授予与关系变化必须发生；不替玩家缔约或接受身份 |

表中的具体名称是示范素材，不由本文新增为世界事实。奖励需要展示时沿用当前适用的物品名片契约；面板出现不能代替真实入库，领取过的奖励不再发放。逐字段 Patch 示例改为明确结果说明，具体字段遵循现行变量结构与更新规则。

```text
终局成立依据：具体发生了哪些事实。
场景收束与人物余波：
实际结局：成功／失败／拒绝后终止等，按本线约定。
奖励或代价：名称、数量、必要属性、领取条件、是否已兑现。
归档：仅本线，防重复；保留持久结果与其他线。
玩家余地：留给玩家决定是否离去、修炼或继续交流。
```

## 6. 小事件组合与完整样例

### 最小组合与规模选择

```text
最小小事件：开始 → 结束
需要调查：开始 → 中间（可交互多轮）→ 结束
需要选择：开始 → 分支 → 相应结束
```

节点图表示情境如何承接，不是固定轮数或新的状态枚举。开始先给出可回应的情境；结束根据真实回应处理后果，可以经过询问、协商和领取等多轮交互。跨轮不等于必须升级长线。只有需要分别保存多段事件进度、长期条件等待或独立幕次加载时，才讨论按长线组织，不能静默迁移。

当前南疆小事件以地区／宗门集合维护；开始时只保存集合内的小事名称和待回应信息，不占长线标题、不建历练、不输出剧情面板。以下为教学素材，人物、物品和数值不自动新增为世界事实；接入时核对现有设定与字段，仅加载被选中的小节。

### 收益梯度与奖励素材

| 梯度 | 适合的结果素材 | 设计核对 |
|---|---|---|
| 高 | 行险成功后的较多收获、重要人情、较强但有期限的状态 | 风险与代价必须先可知，收益不能因选了激进说法就保证成功 |
| 中 | 付费治疗、稳妥拓印、实用丹药或材料 | 明确价格、消耗、实际交付和可用条件 |
| 低 | 普通照料、少量心得、日常好感或消耗品 | 数值与当前境界、经济和人物关系匹配 |
| 无 | 拒绝、绕行、暂不冒险后的平稳收束 | 无奖励不等于惩罚，也不额外赠送修为或隐藏好感 |

梯度供作者比较代价和后果，不强制每事四条路线，不规定选项数量、顺序或前缀，不把内部收益标签输出成角色台词。功法、装备、丹药、符箓、素材、状态、灵石与人物关系都可作为素材；具体数值、品质、效果和标签核对现行物品功法与经济规则，不从参考表直接生成超规格奖励。获得秘籍不等于学会，收到丹药不等于已经服用。

### 样例一：药庐救急（人物互动）

**适用条件**：玩家真实来到百草药庐，已有负伤或中毒事实，陆素心已经登场且在场、好感至少 15；集合允许小事件且尚未完成“药庐救急”。教学中陆素心是医者，不能在用户未授权时凭本文新增到实际卡中。具体伤势必须能被当前治疗处理，不以该例保证所有重伤均能治愈。

**已发生事实**：玩家来到药庐并被医者看见。尚未同意治疗、付费、服药或交代伤因。

#### 开始节点

```text
<event>
[药庐救急·开始]
药炉压着细火，廊下挂着晾干的草束。陆素心从药册上抬眼，留意到来人身上的伤势，放下笔，将干净布巾和药匣移到桌边：“先让我看看伤口？若不方便说来由，也可以只讲哪里不适。”

只写医者提出帮助，不替玩家坐下、递出手腕、脱衣、接受治疗或透露隐私。停在等待玩家回应的位置。治疗的必要风险和收费先讲清，不能先施治再索款。

[记录]
在本集合的事件进度保存小事“药庐救急”及待回应。未处理伤势、未增加好感、未扣钱、未赠药；不建历练、不改长线标题、不输出剧情面板。
</event>
```

#### 真实回应与结束节点

下列路线按实际行动选择，不以关键词机械命中。示例价格 20 灵石仅为教学约定；接入前须核对现行经济规则。恢复量按实际伤势和现行治疗规则确定，不写成无限治疗。

```text
<event>
[药庐救急·回应与结束]
承接玩家本轮实际表达与已发生治疗，不重播开场。

接受普通帮助：玩家明确允许检查及普通包扎后，陆素心检查可见伤处、解释处理方式，在同意范围内清创包扎。只按已实施的治疗记录恢复，不自动清除无关毒性或赠药；实际处理完并结束这次交互后收束。

付费处理：玩家询价时，先说明药膏与一份清心药散合计 20 灵石及适用范围，不扣钱、不治疗。玩家实际同意且支付后才扣费；药膏实际使用才记录治疗，药散实际交到玩家手中才入库一份。获得药散不代表服用。已付款但未交药时保留待交付事实，不能再次收费，也不能提前归档或自动退款。

拒绝：玩家明确谢绝并离开，陆素心收回药匣，不强行施治、不加好感、不发奖励，按无收益结果结束小事。

继续询问／协商：只回答药性、费用、风险或伤势问题，保留待回应。不把问价当购买、不把愿意了解当接受治疗；不写完成令牌。

其他办法：按玩家提出的行动和医者现有能力处理。针法、换药或行险疗法必须另有已确认的技术、风险和结果依据，不因参考提供了收益梯度就强行凑一条高收益路线。

[记录与收束]
只记录实际费用、治疗与交付；已经兑现的结果不因继续询问而重复兑现。治疗或交易实际完成且交互结束，或明确拒绝离场时，按集合规则写入本小事唯一完成记录，清理本集合对应待回应信息。正在交付或继续问询时保持待回应。
</event>
```

**暂缓与重复回应**：暂时去取钱、尚未明确放弃时，不把“以后再来”自动记作失败；保留已发生的支付、治疗与未交付事实，按集合既有接续规则处理。若正文明确结束本次相遇并离场，可按集合约定归档本次小事，但必须先核清未交付事项，不能吞掉已支付的物品。完成后的旧问题不能重新触发赠药或收费。

### 样例二：古阵观悟（无 NPC 环境互动）

**适用条件**：炼气及以上，玩家实际接近宗门后山的废弃石台，本次小事未完成且集合允许触发。石台上残留的阵纹只提供一次有限研习机会，不临时出现 NPC 或隐藏传承人物。

**已发生事实**：玩家能看到阵纹；未触摸、拓印、注入灵气或参悟成功。以下案例不规定统一奖励数值，接入前按既有阵法、物品与经济规则填写具体消耗和效果，不能把这些待核参数当作运行成品。

#### 开始节点

```text
<event>
[古阵观悟·开始]
后山石台覆着薄苔，雨水沿着半圈凹槽缓缓流转。断裂处有微弱灵光随着风势亮起，外圈纹路尚可辨认，内圈则被一道焦痕截断。松针落入凹槽时轻轻一颤，便滑向石台边缘。

呈现可观察的纹路与异常，停在玩家决定远观、拓印、试探或离开之前。不替玩家触碰、盘坐、渡入神识或消耗纸墨，不预判已悟阵理。

[记录]
本集合保存小事“古阵观悟”及待回应，不建幕次与历练，不输出剧情面板，不提前获得拓片、修为或状态。
</event>
```

#### 真实回应与结束节点

```text
<event>
[古阵观悟·回应与结束]
只承接玩家已经声明的行动，可多轮观察；不要求先在四个按钮里选一项。

远观研究：依据玩家的观察和阵法知识，逐步给出水流、凹槽与灵光的关系。只有真实完成一次有效研习，才按预先核定的低档心得记录结果。只是站着看或询问细节不自动增加修为。

稳妥拓印：先核对所需纸墨、灵气及玩家是否同意消耗；实际实施成功才扣除对应消耗并获得一份残阵拓片。拓片的完整度、阅读进度与作用须按当前秘籍／资料契约填写；入库不等于学会阵法。

深入试探：先呈现焦痕处灵力不稳的可感知风险。玩家明确选择试探后，依据其能力与既定规则处理成功、受阻或受伤；只有成功才兑现预先核定的较高收益，不保证行险必得奖励。代价与状态只落实真实发生的部分。

拒绝或绕行：玩家明确放弃且离开时平稳收束，无物品、修为或隐性奖励。

继续观察／暂缓：保持待回应与已发现线索，不凭“参悟”一词立即结算，不为每次观察另建状态；明确离场且本次互动终止后才按集合约定结束。

[记录与收束]
实际获得的拓片、心得、消耗或损伤分别记账一次。行动结果已处理且本次互动结束，或明确放弃离场，才写本小事完成记录并清理对应待回应。已完成后不再次发放研习收益；不清除其他小事、长线记录或玩家模式。
</event>
```

两例的结束节点都允许继续问询、交付和结果确认；“开始 → 结束”描述职责，不能理解为强制两轮完成。

## 7. 长线组合与连续样例

长线分别保存各线进度，以幕加载一段完整事件。一个幕可以包含开始、若干中间交互与分支；中间节点可以重复、绕行或汇流。幕间长期等待与同幕内部交互必须区分，不为每次观察、犹豫、问询创建新阶段。

### 三种组合主干

```text
线性长卷：开始 → 中间1 → 中间2 → 中间3 → …… → 结束
单分支收束：开始 → 中间 → 分支 → 甲线中间 / 乙线中间 → 共同结束
树状多阶段：开始 → 中间1 → 分支1 → 中间2甲/乙 → 分支2 → 中间3 → 多结局
```

以上箭头表示叙事承接，不表示同轮自动推进或固定幕次递增。将节点分组到幕时，为每组写清进入条件与退出标志；下一幕需要什么条件另行明确。不要为了凑固定幕数删掉节点或分支。

### 连续样例：古渡残灯


以下为独立教学案例，不是角色卡中已经发生的剧情，也不自动新增人物、物品或世界书。示例中的 `<event>` 是供作者参考的剧情指令内容；接入时使用本线真实条件配置与当前幕加载方式，不把四段同时无条件注入。玩家行动前提仅在相应行动真实发生后成立。

#### 整体结构与幕划分

```text
第一幕·渡口残灯：开始（守灯人求助）→ 中间（查验阵纹）→ 分支（修复／封存）
幕间等待：保留选择与线索，回到自由模式；玩家可以先去做其他事
第二幕·灯下归舟：中间（按路线实施）→ 结束（交接结果、结算归档）
```

| 幕 | 硬条件与叙事进入条件 | 本幕完成／退出标志 | 后续 |
|---|---|---|---|
| 第一幕 | 炼气及以上；未完成本线；玩家实际来到古渡，当前允许剧情且没有正在进行的其他幕占用 | 已查明残灯故障，玩家明确与守灯人约定修复或封存，并结束这次交谈；明确拒绝全部委托且离场则终止本线 | 修复线寻找一枚导灵铜片；封存线取得一张空白封签；回来后仍由玩家决定是否实施 |
| 第二幕 | 保留第一幕实际路线；修复线拥有导灵铜片，或封存线拥有空白封签；玩家实际回到古渡并愿意处理残灯 | 路线操作真实完成，守灯人检验结果，实际交接报酬且本次交互结束 | 本线归档；若途中暂离，保留当前真实进展，不自动失败 |

材料获取由常规探索或交易处理，不另造“等待材料／待回应”长线阶段。第一幕的拒绝收束应写明无奖励；暂未决定就保持本幕，不强迫选择。

#### 样例一：开始节点——雨夜问灯

**适用时点**：第一幕具备资格，玩家实际走近古渡，尚未接受或拒绝守灯人的请求。

```text
<event>
[第一幕·渡口残灯：开始]
雨水顺着渡亭檐角滴进泥里。渡口铜灯的火苗每隔几息便向河心偏折，照见水下断断续续的旧阵纹。守灯人将一只木匣压在膝上，没有拦路，只问来人是否懂得辨认导灵纹。

叙事先呈现灯焰偏折、水下阵纹与守灯人的询问；不直接揭晓全部故障，不替玩家应答、接匣或走到水边。停在守灯人等候答复之处。

[本幕说明]
玩家愿意调查时，承接查验过程；问价、询问危险或观察守灯人均属于本幕交互。明确拒绝全部请求并离场才按无奖励终止本线；只是暂时不接话不能推定拒绝。

[面板与记录]
本幕实际开启时输出一次完整剧情面板。剧情名“古渡残灯”，状态进行中，难度炼气，幕次第一幕；局势为残灯偏折、渡口旧阵异常，契机为守灯人询问，焦点为是否协助查验，进展为请求已提出、尚未接受，牵涉为古渡守灯人，紧迫为暂无明确期限。
建立本线第一幕历练，本幕进行中为真；只记录请求已经提出，不记录已接委托、已修灯或已获报酬。
</event>
```

这里“第一幕退出”仍按总表判定，出现开场面板并不完成第一幕。若玩家接受，后续轮使用中间节点承接，不重复播放雨夜问灯。

#### 样例二：中间节点——辨认断纹

**前提**：玩家上一轮明确答应查看，并表示蹲在灯座旁观察阵纹；尚未触碰阵心。

```text
<event>
[第一幕·渡口残灯：中间]
承接玩家已声明的观察。灯座外圈有一段铜纹烧黑，内圈却仍保存着缓慢回流的灵光；河面每传来一阵涌浪，断口便漏出一缕细白雾气。守灯人解释：旧灯既为渡船指路，也压着废渡的回流，近日只能勉强维持。

观察足以发现断口，但不能直接判定玩家已经修好阵纹。若玩家询问，可逐步说明两种处理办法：补上导灵铜片恢复灯阵，或用空白封签封住回流、暂停夜渡。不要把所有真相一次说尽，也不额外捏造敌人逼迫玩家行动。

[停笔点]
停在断口与两圈灵纹的作用已经可辨、玩家可以决定继续探查或询问方案的位置。不替玩家伸手试阵、消耗材料或承受未经行动触发的反噬。

[记录]
保持第一幕和本幕进行中，进展记录为已发现外圈断纹、内圈仍在维持。此次只是观察，不记录路线、不消耗物品，不发奖励，也不重复输出剧情面板。
</event>
```

玩家可以在本节点继续数轮问询、核对风险或检查其他痕迹。中间节点按真实反馈重复使用，不因每条新信息创建新幕。

#### 样例三：分支节点——续灯还是封渡

**前提**：玩家已查明断纹，并主动询问可行办法；尚未选定路线。

```text
<event>
[第一幕·渡口残灯：分支]
守灯人把木匣打开，里面只有两张旧阵图。他说明两条路：找一枚导灵铜片补接外圈，可以保住夜渡；找一张空白封签封住内圈，可以先止住回流，但渡口此后夜间停航。两种材料都尚未交付，不能预写已经持有。

两路风险与代价向玩家说明后停笔。不要替玩家答应，不生成固定第五项或带剧情前缀的专属选项。

[分支结果与承接]
修复：玩家明确约定修复后，记录实际路线“修复”，后续目标为取得导灵铜片并回来实施；不记录已修好。
封存：玩家明确约定封存后，记录实际路线“封存”，后续目标为取得空白封签并回来实施；不记录已封住回流。
问询或犹豫：保持第一幕进行中，不记路线、不结束本幕。
其他办法：依据已知阵纹作用和真实能力判断，不按措辞强行匹配上述两路；不能凭提出办法就视为实施成功。
明确拒绝全部请求并离场：本线以未承接收束，按无奖励终止规则归档；普通暂离保留进度。

[本幕结束]
只有路线已明确且这次交谈实际结束，才结束第一幕，保留路线与下一幕线索、释放本线聚焦。不在同轮开启第二幕，不发报酬，不重复输出面板。
</event>
```

修复与封存两路在第二幕分别安排实施过程，均可复用中间节点；其实际结果不同，随后进入相应结束节点。这是分流后汇合到同一类收束节点，不是强行抹平两路后果。

#### 样例四：结束节点——渡灯复明

**前提**：选择修复线，玩家在第二幕已经实际安装并消耗一枚导灵铜片；灯阵恢复，守灯人完成检验。示例设定中事先约定报酬为 20 灵石，且尚未领取；此数值仅用于教学，不是通用奖励标准。

```text
<event>
[第二幕·灯下归舟：结束]
承接已经发生的修复结果。铜灯的光不再偏向河心，水下断续的阵纹连成一圈，细白雾气缓缓沉回水底。守灯人试过灯座，把约定的二十枚灵石放到石台上，说明夜渡可以恢复。

停在报酬可领取、玩家仍可询问或继续交谈的位置。不替玩家拿钱、离开古渡、长期修炼或突破境界。

[结算依据]
只有玩家实际领取时才增加 20 灵石；此前只记录报酬已备妥。导灵铜片在实际安装时已经消耗，不在此再次扣除。没有功法、额外物品、修为或关系奖励。
若玩家明确谢绝报酬，记录其放弃领取，不自动加钱；已领取后再次交谈不重复发放。

[完成与归档]
修复已检验、报酬已领取或明确放弃，且本次交互真正结束后，记录修复路线的实际结局，归档本线并移除本线运行进度与历练。仅在聚焦仍指向本线时清空对应指针，保留其他线及玩家模式。
只是报酬摆上石台或玩家继续问询时，保持第二幕进行中，不提前归档。结束节点不重复输出剧情面板。
</event>
```

**封存路线的对应结束**：前提改为玩家已实际使用并消耗一张空白封签，回流止住、铜灯熄灭，守灯人确认暂停夜渡。按事前相同约定处理 20 灵石报酬，保存“封存、夜渡暂停”的结果；不能沿用修复线的“渡灯复明、夜渡恢复”文案，也不再消耗导灵铜片。两路线均以真实结果和交互结束为归档依据。
## 8. 小事件与长线的运行约定

### 共用边界

无剧情模式不能被 AI 或同步自动覆盖；真实行动与结果才是记录依据。选项遵循全局规则，不强制收益档位、数量或剧情前缀。展示、状态持久化和奖励兑现分别核对。

| 项目 | 当前南疆小事件集合 | 当前南疆长线 |
|---|---|---|
| 调度 | 统一入口让位后评估集合，集合内单轮一个小事件；待回应按集合规则承接 | 当前幕优先，每轮最多开启一幕；同轮不结束一幕后再开下一幕 |
| 记录位置 | `事件.进度[集合名]` 内的小事名称和待回应信息，沿用当前集合结构 | `历练[剧情名]` 分别保存各线幕次、进行中、实际分支与进展 |
| 聚焦 | 不占长线标题、不创建长线阶段 | `事件` 仅作当前聚焦索引，切线不清空其他线进度 |
| 面板 | 不建立剧情历练，不输出剧情面板 | 新幕实际开启仅一次；专属开局按已确认例外 |
| 完成 | 真实收束或明确离场且交接已处理后，按集合规则归档小事、清理对应待回应 | 本幕结束保留历练与线索，全线真正结束／中断才归档 |

不在文档合并中修改变量结构或把其他地区迁入当前南疆机制。

### 长线面板、状态与调度


| 职责 | 现行约定 |
|---|---|
| 条件配置／脚本 | 注册入口、合法幕次、专属资格、无剧情模式、防重开与不可绕过的硬条件；不判断玩家接受、交互完成或自动发奖 |
| 剧情世界书／叙事 AI | 当前幕情境、玩家行动边界、完成／退出标志、下一幕条件；依据真实正文决定是否开启、结束与分支 |
| 普通 MVU 更新 | 在 `历练[剧情名]` 保存幕次、阶段、本幕进行中、实际分支与进展；`事件`聚焦仅为当前索引 |
| 前端 | 展示正文面板与真实历练记录，不以面板显示代替状态写入 |

按当前南疆约定，`阶段`保存配置认可的精确幕次标识，`幕次`用于展示；本幕进行中和幕间等待分开，不以节点用途另造细碎阶段名。具体合法值从本线配置核对，不能由 AI 自由命名。

每轮最多开启一幕；同轮不能完成当前幕后再开启下一幕。当前幕优先，多线分别保存进度。自由模式承接实际行动，手动选择不绕过条件，无剧情模式只有玩家能解除。

### 新幕首次展示的完整面板素材

以下是填写参考，不能把占位文字直接交给模型输出。示例拆行供作者核对字段，实际格式沿用当前解析契约。

```text
<task_info>
剧情名
| 类别: 剧情 | 状态: 进行中 | 难度: 本幕实际难度 |
| 幕次: 本幕展示名 |
| 局势: 已发生的外部局势 |
| 契机: 实际出现的切入点 |
| 焦点: 玩家眼前可处理的问题 |
| 进展: 已发生的内容，不预写选择 |
| 牵涉: 已知的相关人物或势力 |
| 紧迫: 有依据的时限或压力 |
</task_info>
```

新幕实际开启时只输出一次；同幕中间、分支与结束交互不再重复。祖窟首幕已由开局确认页展示并初始化，正文不重复插卡；其他专属开局须核对各自实现，不自动套用此例外。行动选项遵循全局规则，不恢复固定第五项、分支前缀或专属选项样式。

### 归档与中断

- **只结束本幕**：`本幕进行中=false`，保留本线历练、当前幕、分支与下一幕线索；释放当前本线聚焦，等待下一幕。
- **真正完成或不可继续的中断**：按现行规则记录本线完成／中断事实与实际结果，加入防重开记录，移除本线历练及运行进度。
- 清理聚焦指针前检查它仍指向本线；不能清除其他线记录或覆盖玩家的无剧情模式。
- 暂离、手动切线、未表态、提出异议不是自动失败，不能采用“一脱离就强制归档”的处理。
- 需要保存的结局事实、已获得物品与人物关系不能随运行进度一起误删。

## 9. 编写与审阅清单

1. 先画四类节点的组合关系，保留作者确认的分支、门槛、后果和奖励。
2. 小事件填写情境、真实回应、结果和集合收束；长线再将节点分组为完整事件幕，逐幕填写进入条件、内容、玩家边界、退出标志及下一幕条件。
3. 对齐本线的条件配置和世界书，按需读取[门禁条件参考词典](门禁条件参考词典.md)。本文不提供一份可直接运行的全局调度副本；新增接入时检查当前源码，确保示例与实际配置接口一致。
4. 写状态事实。小事件仅加载选中小节，不输出剧情面板；长线按规则出卡，只加载当前幕或幕间下一幕条件摘要。待玩家作出的动作不能预先写入。
5. 对照节点图检查每条路线的进入、承接、汇流、结局和奖励唯一性，避免孤立分支或无出口循环。
6. 先做相关离线检查，再在完整独立测试卡中由助手建议输入、用户发送反馈。同步、发布与模型调用分别按当次授权执行。

### 审阅清单

- 四类节点的作用、可重复使用和组合路径是否仍然完整，而非只剩运行分支占位符？
- 一幕是否允许必要的多轮交互，且未把问询、犹豫或暂离变成新状态或全线失败？
- 所有分支是否写清条件、真实结果、下游承接与暂缓办法？
- 停笔点是否保留玩家决定权，示例中的动作与胜负是否被误当成必然事实？
- 新幕面板、真实变量更新与奖励兑现是否分别检查，且没有重复发卡、发奖？
- 本幕结束与全线归档是否区分，清理是否仅影响本线？
- 未接入地区是否保持原行为，是否明确区分离线验证与真实对话结果？


- 小事件是否仍然不占长线标题、不建历练、不输出剧情面板，并允许合理的多轮交互？
- 接受、付费、拒绝、问询、暂缓、未交付与重复回应是否分别处理，没有提前归档或重复兑现？
