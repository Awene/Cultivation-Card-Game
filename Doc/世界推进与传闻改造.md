# 世界推进与传闻改造（2026-09-06，待统一发布）

## 数据与迁移

传闻由旧数组改为对象，内含 `上次世界推进时间点`（年、月、日、时辰，可为 null）与 `条目` 数组。每条消息的 id、时间区间、世界、地域、地点、类别、内容、难度字段不变。

变量结构预处理器、Zod Schema 和 MVU 核验均兼容旧数组，保留已有消息。MVU 核验仅在推进时间点为空且当前日期有效时填入当前时间；旧存档不追溯补算整个历史。普通回复不能自动覆盖已记录的起点。

前端删除 `timeline-engine.ts` 及自动同步入口，不再生成、剪枝或用旧 localStorage 缓存覆盖传闻；已有浏览器缓存不做破坏性清理，但不再读取。

## 操作与路由

传闻页新增“世界推进”、上次推进时间及当前时间。按钮从最新楼层读取变量，经角色卡脚本校验后填入输入框并自动发送。已有草稿、正在生成、日期无效、时间相等或倒退时拒绝发送；一个时辰的有效跨度也允许。

确定性指令：`请明确以[时间推进规则]进行世界演进。`

仅检测本次玩家输入；重生成、swipe、继续时从对应玩家指令及此前变量快照恢复区间。缺少此前快照时拒绝重生成，避免复用已结算的最新状态。

路由插件 0.19.5 仅提供通用接口：`window.CultivationRuleRouter.requestFixedRoute(enabledNames, reason, options)`，返回一次性请求 id，可通过既有 `cancelRequest(id)` 撤销。固定结果只开启指定候选，关闭其余候选，不展开关联，不修改常驻条目的持久开关。`registerFixedRouteResolver(id, callback)` 允许调用方在生成前提供固定选择，注销函数用于切卡清理；`options.data` 仅作为不透明 JSON 存入楼层 `extra.crr_route.requestData`，插件不解释其业务含义。

新增卡内脚本 `脚本/【本格修仙】世界推进.js`，已登记在 `本格修仙.yaml`。触发短语、时间比较、草稿/重复结算保护、重生成快照、变量核验提示全部在此实现。前端调用 `window.parent.CultivationWorldAdvance.send()`；卡内脚本指定唯一候选 `[时间推进规则]`，请求 `reuseForExtraApi: true`。卸载脚本时清理注册、事件及桥接对象，不影响其它角色卡。插件不再含 `world-advance.js` 或专用 `sendWorldAdvance()`。

移除配置中的修炼/突破关联时间推进；普通模型路由误选时间推进或旧配置关联它时也不会开启。额外变量 API 复用该正文固定结果，优先于普通 skip/off 策略；显式内部请求仍遵守自身控制。

推进时间点由 AI 与人物、传闻更新在同一 JSONPatch 中写为请求记录的终点，脚本不自动标记完成。遗漏时提示；有未结算的世界推进记录时阻止按钮重复发送，建议等待变量更新或检查并重生成。重生成应由 MVU 原有楼层回退机制恢复旧数据，插件不自行叠加更新。

## 规则、提示词与展示

- 只补算上次推进至当前的区间，不额外推进玩家时间，不重复累计已经结算的年龄、修为和物品。
- 推演前关系列表中全部“人物”逐一输出小 `time_info` 面板，接各自经历叙事；必要时补世界变化，最后回到当前玩家。陨落者先展示后按原规则移除。
- 不足一年按实际尺度叙述；人物镜头不等于主角知情，秘密不能直接成为公开传闻。
- 传闻保留有效旧消息，按 id 更新并补新，清理过期或证伪消息；结束日当天仍有效。
- 正文字数目标为 2500—3500，面板不计；全员展示优先，人数多时允许超出。其他回合保持原字数。
- 变量更新规则按路由显示传闻结构；未开启时只读。额外记录模型只在世界推进时收到传闻数据。
- 世界推进时剧情模型也能读取各人物的物品等细节，用于准确推演；普通回合继续尊重前端“细节可见”设置。生日等本地核验字段仍隐藏。
- 正文小面板复用并压缩原渲染，兼容旧大面板；传闻手机布局调整为标签、日期地点、内容分层，避免窄屏挤压。
